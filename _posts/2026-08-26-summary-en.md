This marks the first time the format will be on by default in a major browser, moving it out of behind-flag status. With Firefox and Chromium both moving toward jxl-rs \(a Rust-based implementation\), JPEG XL is gaining real momentum as a viable next-generation web image format. Its main rivals on the web are AVIF \(based on AV1 video coding\) and WebP \(Google&\#x27;s earlier format\). Despite technical advantages, adoption has been slow because no major browser had enabled it by default until now.

On Android, the C2PA Conformance Program requires that signing operations be backed by a hardware Root of Trust, which Google provides through Key Attestation, a feature that lets an app prove that a cryptographic key was generated and stored inside secure hardware \(such as a TPM or secure element\).

## [Python str.lower\(\) as a Security Vulnerability via Unicode Case Folding](https://sethmlarson.dev/when-str-lower-is-a-security-vulnerability) ⭐️ 7.0/10

Seth Larson, a CPython core developer, published an analysis explaining how Python&\#x27;s str.lower\(\) method can introduce security vulnerabilities due to Unicode case-folding behavior. The article specifically highlights mismatches between Unicode versions used by str.lower\(\) and the version required by standards like IDNA \(Internationalized Domain Names in Applications\). This matters because any application performing case-insensitive comparisons or domain name normalization — such as URL parsers, email validators, and authentication systems — could be vulnerable to spoofing or bypass attacks. Developers commonly assume str.lower\(\) is safe and locale-neutral, but Unicode case-folding can produce surprising character mappings \(e.g., Turkish dotless i\) that break security assumptions. Python&\#x27;s str.lower\(\) uses full Unicode case mapping \(which can produce multiple characters\), while re.IGNORECASE uses simple case folding \(single character output\), creating inconsistency. The article recommends using Unicode 3.2.0 case-folding rules for IDNA compliance, which differs from what str.lower\(\) currently implements.

rss · Hacker News \(热门\) · Aug 25, 20:49

**Background**: Unicode defines two related but distinct concepts: lowercase mapping and case folding. Lowercase mapping is language-aware \(e.g., Turkish has unique rules for the letter &\#x27;i&\#x27;\), while case folding is designed to be language-neutral for consistent comparisons. IDNA processing requires case folding based on Unicode 3.2.0 to ensure domain names are handled consistently worldwide. When str.lower\(\) uses newer Unicode rules than the specification requires, characters that were distinct in older versions may now collide, enabling homograph attacks where visually similar characters from different scripts are treated as identical.

## [.NET 10 BufferedStream WriteByte Drops Implicit Flush Behavior](https://dev.to/ssukhpinder/net-10-bufferedstream-writebyte-flush-full-buffers-explicitly-45a2) ⭐️ 6.0/10

Starting with .NET 10, BufferedStream.WriteByte no longer calls Flush\(\) on the underlying stream when the internal buffer reaches its capacity boundary. The buffer still drains to the underlying stream to make room, but the explicit Flush\(\) method call is removed, aligning WriteByte with the other Write overloads. This is a behavioral change shipped in the .NET 10 LTS release that can silently break applications relying on Flush\(\) side effects at the buffer boundary — for example, custom streams, protocol adapters, compressors, or test doubles where Flush\(\) triggers an observable action. Developers upgrading to .NET 10 should audit code that wraps BufferedStream around such streams. Verified with SDK 10.0.303 and runtime 10.0.11, while the old contract was reproduced against runtime 9.0.18. The change only affects the Flush\(\) method call on the underlying stream; buffered bytes still flow to the destination when room is needed, and Flush\(\)/Dispose\(\) remain the only ways to trigger an explicit flush.

rss · Dev.to · Aug 25, 23:26

**Background**: BufferedStream is a standard .NET wrapper that adds an in-memory buffer in front of another stream to reduce the number of expensive I/O operations. Its internal buffer has a fixed capacity; when full, it drains bytes to the underlying stream to make room. Historically, WriteByte had a unique quirk: it called Flush\(\) on the wrapped stream at that capacity boundary, unlike Write\(byte\[\], int, int\) or Write\(ReadOnlySpan&lt;byte&gt;\). In .NET 10, Microsoft removed this inconsistency so that Flush\(\) is invoked only when the developer explicitly calls it or disposes the BufferedStream.
