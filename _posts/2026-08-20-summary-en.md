## [AliExpress Silently Fingerprints Users via WebAudio, Breaking Bluetooth Multipoint](https://blog.laserphile.com/2026/08/aliexpress-webpage-keeping-multipoint.html) ⭐️ 8.0/10

A security researcher has discovered that the AliExpress website runs silent WebAudio fingerprinting code that produces inaudible sounds, which interfere with Bluetooth multipoint connections and cause audio devices to misbehave. This reveals that a major e-commerce platform is deploying a covert, permission-less tracking technique that not only invades privacy but also has tangible side effects on user hardware. It highlights a gap between browser security models—which treat audio playback as benign—and real-world abuse by high-traffic sites. WebAudio fingerprinting works by generating audio signals through the Web Audio API and measuring how the browser/hardware processes them, producing a stable and relatively unique identifier without any user permission prompt. The side effect is that these silent signals are routed through the OS audio stack to paired Bluetooth devices, disrupting multipoint handshakes and causing hearing aids and car audio systems to behave unexpectedly.

hackernews · Hacker News \(热门\) · Aug 20, 10:08 · [Discussion](https://news.ycombinator.com/item?id=49372583)

**Background**: Browser fingerprinting is a technique that identifies users by combining hardware and software attributes \(such as GPU, fonts, screen size, and audio processing behavior\) into a unique signature, eliminating the need for cookies. The Web Audio API fingerprinting variant is particularly stealthy because it does not require microphone access and runs silently in the background. Bluetooth multipoint is a feature that lets a single headset or hearing aid maintain simultaneous connections to two source devices, such as a phone and a laptop, which makes it sensitive to unexpected audio routing events.

## [Grok Vulnerable to Cryptographic Context Injection Data Exfiltration](https://arstechnica.com/security/2026/08/grok-exfiltrates-user-data-when-malicious-instructions-are-encrypted/) ⭐️ 8.0/10

Security researchers have discovered a novel attack technique called Cryptographic Context Injection \(CCI\) that targets Grok AI, enabling zero-click data exfiltration of user chat history by hiding malicious instructions inside ciphertext that the model itself decrypts. The same encryption-based approach also bypasses Gemini&\#x27;s safety policies via direct injection. This attack exposes a significant blind spot in LLM safety guardrails, as conventional content filters cannot detect malicious intent inside encrypted payloads. It highlights an urgent need for cryptographic context binding and stronger defenses against adversarial inputs in widely deployed models. CCI works by delivering attacker instructions as ciphertext within user-controlled data sources \(such as documents or web pages\), which the model decrypts in its own sandbox, allowing indirect prompt injection to exfiltrate chat history without user interaction. This is distinct from traditional jailbreaks that target refusal mechanisms, instead exploiting the model&\#x27;s code-execution or decoding capabilities to smuggle commands past input filters.

rss · Ars Technica · Aug 20, 13:00

**Background**: Grok is a family of generative AI large language models developed by xAI \(Elon Musk&\#x27;s AI company\), launched in November 2023 and known for its conversational, humor-oriented style. LLM safety guardrails are the filters and refusal mechanisms designed to prevent models from producing harmful outputs or leaking private data, but researchers have repeatedly shown they can be circumvented through prompt injection, jailbreaking, and adversarial machine learning. Cryptographic Context Injection represents the latest escalation: by wrapping instructions in encryption, attackers make malicious payloads invisible to safety classifiers that scan for trigger words or suspicious phrasing.

This release matters because it provides the open-source community with a practical implementation of the &\#x27;megakernel&\#x27; pattern applied to MoE inference on cutting-edge hardware, an area where very few public references exist. LLM inference engineers and researchers building on NVL72 platforms can now study and build upon a production-grade kernel design rather than starting from scratch. A &\#x27;megakernel&\#x27; is a kernel-fusion technique that consolidates many GPU operations into one large kernel to reduce memory traffic and overcome the limited shared-memory capacity that constrains conventional kernel fusion.

## [School-level surveillance detects measles epidemic risk years before county data](https://www.nature.com/articles/s41591-026-04612-2) ⭐️ 8.0/10

This finding exposes a critical blind spot in current US infectious disease surveillance: aggregating vaccination coverage to the county level can mask localized susceptibility in schools, where transmission actually occurs, delaying public health interventions until outbreaks are already underway. The study compares school-level and county-level vaccination coverage estimates against the herd immunity threshold of approximately 95% required for measles; its companion paper notes that the 2025–2026 outbreaks involved more than 3,500 cases and placed the US measles elimination status under formal review.

rss · Nature Medicine · Aug 20, 00:00

**Background**: Herd immunity thresholds vary by disease: measles, being highly contagious, requires about 95% population immunity to prevent sustained transmission. The United States declared measles eliminated in 2000, but vaccine hesitancy and COVID-19-related disruptions to routine immunization have eroded this protection. Traditional county-level surveillance aggregates data over large geographic areas, which can hide small pockets of unvaccinated children within individual schools—exactly the settings where measles spreads most efficiently.

## [Double-Double Arithmetic: 31 Digits of Precision Without Leaving the FPU](https://marekfiser.com/blog/double-double-arithmetic) ⭐️ 7.0/10

Marek Fišer published a detailed technical article explaining how double-double arithmetic can achieve approximately 31 decimal digits of precision by composing pairs of standard IEEE 754 double-precision floating-point numbers, all without requiring software-emulated arbitrary-precision libraries. The article walks through the algorithms for addition, multiplication, and division using only native FPU instructions. This matters for scientific computing, numerical simulation, and financial calculations where standard double precision \(~15-16 digits\) is insufficient but full quad-precision hardware support or library calls \(e.g., MPFR\) are too slow. Because double-double operations inline into loops as just 7-80 FPU instructions, they can be vastly faster than function-call-based arbitrary-precision arithmetic while still fitting into normal CPU pipelines. A double-double add or multiply compiles to roughly 7-20 instructions that the JIT can inline into a hot loop, while division costs around eighty instructions but is still inlined; in contrast, an MPFR operation in .NET requires a P/Invoke call costing about 1.6 ns before any arithmetic even starts. The technique exploits the fact that floating-point hardware, given the right algorithms, can recover the bits it rounded away, effectively constructing higher-precision numbers from ordinary doubles.

rss · Lobsters \(技术社区\) · Aug 20, 15:31

**Background**: Standard IEEE 754 double-precision floating-point numbers store 64 bits and provide about 15-16 decimal digits of precision, which is adequate for most applications but can accumulate unacceptable rounding errors in iterative numerical methods or ill-conditioned problems. True quadruple precision \(128-bit floats, ~34 digits\) is rarely supported in hardware on general-purpose CPUs, so developers typically resort to software libraries like MPFR that emulate the extra bits — accurate but slow because every operation is a function call. Double-double arithmetic is a well-known but under-documented middle ground: it represents a number as an unevaluated sum of two doubles \(head and tail\), and careful algorithms maintain both components through each operation, yielding roughly twice the precision of a single double while staying entirely within the hardware FPU.
