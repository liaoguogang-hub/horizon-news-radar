## [CUDA-for-AMD-Windows：让 AMD GPU 运行 CUDA 代码](https://github.com/Speedstu/CUDA-for-AMD-Windows) ⭐️ 7.0/10

开发者 Speedstu 在 GitHub 上发布了名为「CUDA for AMD on Windows」的项目，这是一款旨在让 CUDA 代码能够在 Windows 环境下运行于 AMD GPU 上的工具，试图弥合 NVIDIA 专有 CUDA 生态与 AMD 硬件之间长期存在的兼容性鸿沟。 该工具解决了开发者的一个重大痛点：他们希望使用 AMD GPU，却受到 CUDA 在 AI、科学计算和高性能计算领域主导地位的制约。如果可行，它可以降低 AMD GPU 的使用门槛，尤其是在 ROCm 支持有限的 Windows 平台上，有望为开发者提供更大的硬件选择自由度。 该项目仓库页面提供的实现方法和性能特征等技术细节有限，关于它如何处理 CUDA 专有 API 以及是否需要修改或翻译代码仍存疑问。类似的过往项目（如 ZLUDA）曾面临法律挑战——NVIDIA 于 2024 年 3 月在 CUDA 最终用户许可协议中明确禁止使用翻译层——而 AMD 的 HIPIFY 等工具已经为跨平台开发提供了从 CUDA 到 HIP 的源码级翻译路径。

rss · Hacker News \(热门\) · 9月13日 14:25

**背景**: CUDA（Compute Unified Device Architecture，计算统一设备架构）是 NVIDIA 的专有并行计算平台和 API，于 2007 年发布，已成为 AI 和高性能计算领域 GPU 加速的事实标准。AMD 的竞争平台 ROCm 历史上在 Linux 上的支持远强于 Windows，这给拥有 AMD 硬件的 Windows 开发者带来了障碍。ZLUDA 等工具曾试图为非 NVIDIA GPU 提供即插即用的 CUDA 替代方案，而 AMD 的 HIPIFY 则提供了从 CUDA 到 AMD HIP 语言的源码级翻译。NVIDIA 在 2024 年收紧最终用户许可协议以禁止翻译层，给此类项目增添了法律风险。

## [Rust 永不类型在历经 11 年后正式稳定](https://lwn.net/SubscriberLink/1091015/d9e48318ed242b41/) ⭐️ 7.0/10

Rust 的永不类型 \`\!\` 在 nightly 编译器特性开关后历经 11 年终于正式稳定，计划随 Rust 1.100.0 于 11 月 12 日发布。LWN.net 的文章深入分析了这一稳定化与类型推断、trait 一致性以及穷尽性检查之间的交互，以及它将给现有代码带来的变化。 永不类型是 Rust 类型系统的基石，支撑着 \`panic\!\(\)\`、无限循环和发散函数等模式。它的稳定化解决了显式类型标注与类型推断回退机制之间长期存在的冲突——此前发散表达式默认回退到单元类型 \`\(\)\`——这将影响整个 Rust 生态系统中泛型、死代码消除以及 trait 实现的运行方式。 与 \`std::convert::Infallible\` 不同，\`\!\` 类型可以强制转换为任何其他类型，这意味着此次过渡需要谨慎处理推断边界情况，因为强制转换会在不对类型变量施加有意义约束的情况下成功。此外，稳定化还与 Rust 1.92 引入的默认拒绝（deny-by-default）的 lint 配合使用，以便在完全切换之前暴露受影响的代码。

rss · Lobsters \(技术社区\) · 9月13日 14:00

**背景**: 在 Rust 中，永不类型 \`\!\` 表示永远不会产生值的计算，例如总是 panic 或永远运行的函数。因为它没有实例，\`\!\` 可以强制转换为任何类型，使其在泛型代码中极为灵活。长期以来，编译器在类型推断时通过回退到单元类型 \`\(\)\` 而不是 \`\!\` 来处理发散表达式，这常常导致令人困惑的推断行为。由 lang-team 的 never-type 倡议所跟踪的稳定化工作将这一回退改为 \`\!\`，使语言语义与编译器推断引擎之间的一致性终于得以实现。
