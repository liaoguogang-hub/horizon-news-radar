## [LLM-Assisted Lean Proving Makes zstd Verification Practical](https://www.imperialviolet.org/2026/07/26/zstd-lean.html) ⭐️ 8.0/10

Adam Langley of Google demonstrated that LLM-assisted Lean theorem proving made it practical to formally verify a zstd decoder, arguing that proof automation has crossed a meaningful threshold of usefulness. Formal verification has traditionally been prohibitively expensive—roughly 20x the cost of normal development—limiting its use to critical code paths. If LLMs can reliably automate much of the proof-writing burden, verification could become economically viable for far more software, reshaping security engineering and the economics of bug prevention. The case study focuses on a zstd \(Zstandard\) decoder, a real, non-trivial compression library originally developed by Facebook. The author notes the cost ratio between formal verification and ordinary development, and frames this as evidence that the field has reached a tipping point where LLM-driven automation meaningfully reduces human proof-writing effort.

hackernews · Hacker News \(热门\) · Jul 26, 20:53 · [Discussion](https://news.ycombinator.com/item?id=49062291)

**Background**: Formal verification uses theorem provers like Lean to mathematically prove that software behaves exactly as specified, rather than relying on testing alone. Lean is an open-source proof assistant developed since 2013 that combines functional programming with dependent types, allowing properties of programs to be expressed and checked at compile time. zstd \(Zstandard\) is a widely used fast compression algorithm developed by Facebook, with a decoder that handles entropy coding and frame parsing—logic well-suited to formal specification but historically too costly to verify in full.

## [Inside the Gray Market for Resold LLM API Tokens](https://simonwillison.net/2026/Jul/26/relay-market/#atom-everything) ⭐️ 8.0/10

An investigation by Matt Lenhard, highlighted by Simon Willison, reveals a thriving gray market—largely based in China—where resellers sell discounted access to LLM APIs by pooling credentials obtained through free-trial abuse, unprotected support-bot endpoints, stolen credit cards, and chargeback attacks. The resellers operate using legitimate open-source proxy tools, primarily one-api and its more actively maintained fork new-api, which are designed to load-balance requests across multiple API keys. This ecosystem poses a direct revenue and security threat to LLM providers, while simultaneously creating financial losses for victims of stolen-card fraud and unfair costs for legitimate users subsidizing free-trial abuse. It also makes it riskier for independent developers to expose LLM-powered apps publicly, since any newly discovered unprotected endpoint can quickly be monetized through this relay market. The buyers of these relay services are typically seeking cheaper tokens, bypassing geographic restrictions, or harvesting outputs for model distillation—a technique used to train smaller models on the outputs of larger ones. Simon Willison specifically calls on LLM vendors to ship strict, user-configurable per-key spending caps \(for example, a hard dollar threshold per time period\) so that abuse translates to a bounded, predictable cost.

rss · Simon Willison \(AI 跨行业洞察\) · Jul 26, 19:30

**Background**: An LLM API proxy is a server that sits between an end user and one or more upstream model providers, forwarding requests while handling concerns such as load balancing, key rotation, and protocol conversion. The open-source projects one-api and new-api are legitimate tools widely used for these purposes, but their ability to aggregate many credentials and resell access makes them ideal infrastructure for the abuse described. A chargeback attack, in this context, typically means a fraudster funds an LLM account with a stolen card, consumes tokens, then disputes the charge—leaving the API provider to absorb the loss while the reseller keeps the profit.

## [MoonshotAI Releases 3T-Parameter Kimi-K3 on HuggingFace](https://huggingface.co/moonshotai/Kimi-K3) ⭐️ 7.0/10

MoonshotAI has released Kimi-K3, a ~3 trillion parameter open-weight language model on HuggingFace, becoming the first open-source model to reach the 3-trillion-parameter class. The model uses Kimi Delta Attention \(KDA\) and Attention Residuals, and natively supports MXFP4 quantization to reduce its hosting footprint. Kimi-K3 sets a new scale benchmark for open-weight LLMs and will give the community real-world data on inference pricing for 3T-parameter models. Its release intensifies the competitive pressure that has already driven API prices down ~45% in recent months, affecting how third-party providers price frontier-tier access. Despite MXFP4 quantization, hosting Kimi-K3 requires roughly 1.5TB of VRAM, pushing the limits of an 8x B200 setup and realistically demanding 16x B200s for adequate context length and throughput. The model&\#x27;s KDA mechanism is a linear-attention variant designed to keep million-token context economically viable, and full open-source weights were scheduled for July 27.

hackernews · Hacker News \(热门\) · Jul 27, 06:18 · [Discussion](https://news.ycombinator.com/item?id=49065752)

**Background**: Open-weight LLMs are models whose trained parameters are publicly released, allowing anyone to download, run, or fine-tune them. As model sizes have grown into the trillions of parameters, hosting them requires enormous amounts of GPU memory \(VRAM\), which is typically measured per parameter and per quantization format; for example, a 70B model in 4-bit precision needs roughly 40GB of VRAM. Frontier-class releases from Chinese labs like MoonshotAI, DeepSeek, and Z.AI have been driving an aggressive price war on inference APIs accessed through aggregators such as OpenRouter.

## [Mike Acton&\#x27;s Foundational Data-Oriented Design Presentation](https://www.gamedevs.org/uploads/introduction-to-data-oriented-design.pdf) ⭐️ 7.0/10

A well-known PDF presentation on Data-Oriented Design \(DoD\) by Mike Acton is being discussed and shared, originally delivered at CppCon 2014. The post highlights the talk&\#x27;s enduring relevance, links to Acton&\#x27;s recently released LLM skill for Data-Oriented Programming, and points to the Odin programming language as a modern adopter of DoD principles. DoD is an important optimization paradigm that focuses on cache-friendly data layouts and data-first thinking, particularly relevant for game development and high-performance systems programming. Despite being over a decade old, Acton&\#x27;s presentation remains a foundational reference, continuing to shape how engineers think about performance, memory access patterns, and system architecture. The talk emphasizes two core DoD principles: understanding the data is essential to understanding the system, and software design should be driven by data transformations rather than abstractions. Commenters also note that DoD has inspired the Odin language and a new LLM-based tooling approach for data-oriented programming workflows.

hackernews · Hacker News \(热门\) · Jul 26, 18:11 · [Discussion](https://news.ycombinator.com/item?id=49060724)

**Background**: Data-Oriented Design is a software design approach, distinct from a programming paradigm, motivated by efficient CPU cache usage. Instead of organizing code around objects or functions as in object-oriented or functional programming, DoD organizes code around the structure, layout, and flow of data — sorting and separating fields to optimize memory access patterns. It is especially popular in video game development, where cache misses can dramatically affect frame rates. Mike Acton, formerly at Insomniac Games and later at Unity, is one of its most prominent advocates. The Odin language, designed by Bill Hall, has built DoD principles into its core philosophy.
