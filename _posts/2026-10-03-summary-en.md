## [Cloudflare Launches OHTTP Gateway for Network Privacy](https://blog.cloudflare.com/announcing-cloudflare-ohttp-gateway/) ⭐️ 7.0/10

Cloudflare has announced its Oblivious HTTP \(OHTTP\) Gateway, a privacy-enhancing service that uses cryptographic separation to ensure no single entity—including Cloudflare itself—can simultaneously see a client&\#x27;s identity \(IP address\) and the content of their requests. As a major infrastructure provider handling a significant portion of internet traffic, Cloudflare&\#x27;s adoption of OHTTP as a managed service makes strong network privacy more accessible to application developers who lack the expertise or resources to deploy such cryptographic infrastructure themselves. It also signals growing industry momentum behind IETF-standardized privacy protocols. The architecture involves three parties—a client, a relay, and an application server—with the OHTTP Gateway sitting between the relay and app server to handle encapsulation/decapsulation, meaning the app server only processes plain HTTP. Cloudflare also offers an open-source relay \(privacy-gateway-relay\) that organizations can self-host if their application servers run outside Cloudflare.

hackernews · Hacker News \(热门\) · Oct 3, 03:15 · [Discussion](https://news.ycombinator.com/item?id=49941091)

**Background**: Oblivious HTTP \(OHTTP\) is an IETF network protocol designed to enable anonymous HTTP transactions by separating who you are \(your IP address\) from what you&\#x27;re requesting \(the request content\). Traditional HTTPS still allows the server to see both pieces of information, which enables tracking and profiling. OHTTP addresses this by routing requests through a relay that only sees ciphertext, combined with an inner layer that the destination server can decrypt—but it cannot link back to the sender&\#x27;s IP. Binary HTTP \(RFC 9292\) is used as the underlying transport for OHTTP&\#x27;s encrypted messages.

## [1989 SELF Compiler Customization Paper: Type Specialization for Dynamic Languages](https://dl.acm.org/doi/epdf/10.1145/74818.74831) ⭐️ 7.0/10

This 1989 paper from ACM introduces customization techniques for compiling dynamically-typed object-oriented languages, achieving 2x performance by generating multiple compiled copies of a procedure, each tailored to a specific receiver type. The authors combine compile-time message lookup, type prediction with runtime type tests, call splitting, and aggressive procedure inlining to recover static type information from declaration-free programs. These techniques laid the groundwork for modern JIT compilers such as HotSpot and V8, which rely on type feedback and inline caching to specialize machine code for frequently observed types. Understanding this foundational work helps explain how today&\#x27;s high-performance JavaScript, Python, and Java runtimes overcome the inherent performance penalty of dynamic typing. The paper&\#x27;s three core innovations are per-receiver-type code specialization \(compiling multiple copies of a routine for different receiver types\), type prediction with runtime verification guards \(falling back to general code if the prediction fails\), and call splitting \(optimizing each branch of a call site for the type that flows along that path\). The reported 2x speedup was measured on SELF, a prototype-based dynamically-typed language descended from Smalltalk.

rss · Lobsters \(技术社区\) · Oct 3, 20:59

**Background**: SELF is a dynamically-typed, prototype-based object-oriented language created at Xerox PARC and Stanford in the late 1980s as a successor to Smalltalk. Unlike class-based languages such as C++ or Java, SELF objects inherit behavior directly from other objects \(prototypes\) rather than from classes. Because the language has no static type annotations, the compiler cannot know the exact type of a variable or expression at compile time, forcing it to emit conservative, slower machine code that handles all possible type combinations. Just-in-time \(JIT\) compilation, later popularized by Sun&\#x27;s HotSpot JVM and Google&\#x27;s V8, addresses this problem by observing runtime type information and recompiling hot code paths with more specific type assumptions.

## [Nutrient Supplements Boost Measles Vaccination in Northern Nigeria](https://www.nature.com/articles/s41591-026-04675-1) ⭐️ 6.0/10

A pragmatic, superiority, cluster-randomized trial conducted in Yobe State, northern Nigeria, found that distributing small-quantity lipid-based nutrient supplements \(SQ-LNS\) alongside routine immunization services substantially increased measles vaccination uptake among children aged 12–23 months. This finding demonstrates a practical strategy for integrating nutritional and immunization programs in low-resource settings, potentially addressing both malnutrition and low vaccine coverage simultaneously in vulnerable populations. The trial used a cluster-randomized design, meaning that groups of participants rather than individuals were randomly assigned to intervention or control arms, which is well-suited for community-level health interventions. The supplements targeted children in a narrow age window \(12–23 months\), aligning with the recommended age for measles vaccination.

rss · Nature Medicine · Oct 2, 00:00

**Background**: Small-quantity lipid-based nutrient supplements \(SQ-LNS\) are food-based supplements designed to prevent malnutrition in children aged 6–24 months. Previous evidence has shown that SQ-LNS can reduce severe wasting and stunting among young children in vulnerable populations. Measles remains a major cause of childhood morbidity and mortality, and vaccination coverage in northern Nigeria has historically been suboptimal. A cluster-randomized trial randomizes groups \(such as communities or clinics\) rather than individuals, which is commonly used when an intervention is delivered at the community level.
