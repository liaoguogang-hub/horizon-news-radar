## [PwnEscape: Guest-to-Host KVM Virtualization Escape Demonstrated](https://pwn.ai/blog/pwnescape) ⭐️ 8.0/10

Security researchers from pwn.ai have disclosed a vulnerability called PwnEscape \(assigned CVE-2026-99999\), demonstrating a guest-to-host escape in the KVM virtualization stack that allows code execution on the host from within a guest VM. The research appears to target the Linux kernel&\#x27;s KVM hypervisor, joining a growing list of VM escape vulnerabilities disclosed in recent years. A guest-to-host VM escape undermines the fundamental isolation guarantee that cloud providers, enterprises, and infrastructure-as-a-service platforms rely on. If exploited, an attacker running inside a single guest VM could potentially access the hypervisor and compromise every other VM running on the same host, with cascading consequences across multi-tenant cloud environments. The CVE identifier CVE-2026-99999 appears to be a placeholder or potentially fabricated number, which is unusual for a formal vulnerability disclosure and raises questions about the legitimacy of the report. The blog post content itself was not directly accessible for technical verification, but similar recent KVM flaws such as Januscape and Zapscape \(CVE-2026-64561\) have exploited use-after-free and shadow MMU bugs respectively, suggesting PwnEscape may follow comparable attack patterns in the x86 KVM subsystem.

rss · Lobsters \(技术社区\) · Oct 17, 18:24

**Background**: KVM \(Kernel-based Virtual Machine\) is a Linux kernel module that turns the kernel into a Type-1 hypervisor, enabling full hardware virtualization on x86 systems. A virtual machine escape occurs when malicious code running inside a guest VM breaks out of its isolation boundary to execute on the host or hypervisor, gaining access to other VMs and the underlying host system. Such vulnerabilities are categorized under MITRE ATT&amp;CK technique T1611 \(Escape to Host\) and represent some of the most critical security issues in cloud computing, as they erode the trust boundary that separates tenants in shared infrastructure.

## [Reverse-Engineering the Intel 8087 Floating-Point Microcode](https://www.righto.com/2026/10/8087-addition-subtraction-microcode.html) ⭐️ 7.0/10

Ken Shirriff has published a detailed reverse-engineering analysis of the Intel 8087 floating-point coprocessor, examining its microcode and circuitry to explain exactly how floating-point addition and subtraction are implemented, including numerous special cases. The 8087 was a landmark chip that brought hardware-accelerated floating-point arithmetic to x86 computing, and understanding its low-level implementation offers valuable insights into how early FPUs balanced correctness, performance, and hardware simplicity — lessons still relevant to modern CPU and FPU design. The article covers the 8087&\#x27;s microcode-level implementation of addition and subtraction, including special cases such as denormals, infinities, NaNs, and gradual underflow handling. It also notes that the 8087 provided up to a 100× speedup for floating-point addition compared to the 8086 alone.

rss · Lobsters \(技术社区\) · Oct 18, 17:59

**Background**: The Intel 8087, announced in 1980, was the first floating-point coprocessor for the 8086 microprocessor line. It was designed to accelerate floating-point arithmetic including addition, subtraction, multiplication, division, and square root — operations that were extremely slow when emulated in software on the 8086. The 8087 used microcode, meaning its operations were implemented through low-level firmware instructions stored on-chip, and it established the x87 floating-point instruction set that influenced all subsequent x86 CPUs. Floating-point addition and subtraction require aligning the significands \(mantissas\) of two numbers based on their exponents before performing the arithmetic, a process with many edge cases.

## [Integrating Ghidra with CBMC for Assembly Model Checking](https://www.philipzucker.com/asmc_cpp/) ⭐️ 7.0/10

Philip Zucker has published a project that integrates Ghidra, the NSA&\#x27;s open-source reverse engineering tool, with CBMC, a bounded model checker for C/C++, to enable formal verification of x86 assembly code at the binary level. This integration bridges reverse engineering and formal methods, allowing security researchers and verification engineers to apply rigorous mathematical proofs directly to compiled binaries rather than relying solely on source-level verification. It has potential impact on malware analysis, vulnerability auditing of closed-source software, and verification workflows where source code is unavailable. The approach likely leverages Ghidra&\#x27;s decompiler to lift x86 assembly into an intermediate representation that CBMC can consume, since CBMC traditionally operates on C/C++ source. Being a bounded model checker, CBMC requires restricting inputs to bounded sizes, meaning verification results are valid only within those bounds unless further invariants are established.

rss · Lobsters \(技术社区\) · Oct 18, 16:58

**Background**: Ghidra is a free and open-source reverse engineering tool developed by the NSA, released publicly in 2019, that supports a wide variety of processor instruction sets and executable file formats; it can be extended through Java or Python scripts. CBMC \(C Bounded Model Checker\) is a formal verification tool that checks C and C++ programs for memory safety, undefined behavior, and user-specified assertions by exploring execution paths up to a bounded depth. It has been adopted in industry, notably at Amazon Web Services, and also serves as the foundation for verifiers targeting other languages such as Rust \(Kani\) and Java \(JBMC\).
