## [Go Adds Experimental Platform-Independent SIMD Support](https://go.dev/blog/simd-experiment) ⭐️ 8.0/10

The Go team announced an experimental platform-independent SIMD package that delivers approximately 5x speedup over scalar Go code while remaining only about 11% slower than architecture-specific intrinsics. The new API allows developers to write vectorized code that compiles across architectures without needing platform-specific assembly. This significantly lowers the barrier to high-performance computing in Go by eliminating the need for CGO or hand-written assembly to exploit CPU SIMD instructions. It enables competitive performance for workloads like ML inference, image processing, and cryptography entirely in pure Go. The package supports transition to and from architecture-specific SIMD via a ToArch\(\) conversion method on each vector type. Notably, the design is the first portable SIMD solution to handle non-fixed-width vector ISAs like ARM SVE and RISC-V V extension, as highlighted by practitioners in the discussion.

hackernews · Hacker News \(热门\) · Sep 25, 11:47 · [Discussion](https://news.ycombinator.com/item?id=49843269)

**Background**: SIMD \(Single Instruction, Multiple Data\) is a class of parallel computing where one instruction operates on multiple data points simultaneously, available on modern CPUs through instruction set extensions like SSE, AVX on x86, NEON/SVE on ARM, and V extension on RISC-V. Traditionally, exploiting SIMD required either compiler auto-vectorization or writing platform-specific intrinsics or assembly, both of which are cumbersome and non-portable. Recent portable SIMD efforts include Rust&\#x27;s portable SIMD crate, the Fearless SIMD initiative, and the upcoming std::simd in C++26.

## [SourceHut Account Takeover via ansi2html.py XSS Vulnerability](https://blog.arusekk.pl/posts/srht-account-takeover/) ⭐️ 8.0/10

A wormable cross-site scripting \(XSS\) vulnerability, tracked as CVE-2026-92973, was discovered in the ansi2html.py library \(versions 1.7.0a0 through 1.9.3\) used by SourceHut to render ANSI escape codes as HTML in build logs. The flaw allowed anyone able to inject text into a builds.sr.ht job log to execute arbitrary JavaScript in the browser of any user viewing that log, including administrators. This vulnerability is particularly severe because it is wormable and can compromise accounts of users \(including admins\) who merely view a malicious build log, enabling potential account takeover across the platform. It highlights the critical importance of properly sanitizing terminal escape sequences in any CI/CD or build-log rendering pipeline, as ANSI/OSC 8 hyperlink support introduces a new and easily overlooked attack surface. The root cause was improper sanitization of OSC 8 hyperlink escape sequences, which let an attacker craft an href with embedded HTML attributes such as onfocus handlers. The vulnerability received a CVSS score of 6.1 \(medium severity\) and affects not only SourceHut but also any other project or instance using ansi2html in the affected version range.

rss · Lobsters \(技术社区\) · Sep 24, 20:38

**Background**: SourceHut is a developer forge platform offering Git repositories, CI/CD builds, mailing lists, and bug trackers, often used by open-source developers as a lightweight alternative to GitHub. CI/CD build logs typically contain raw output from compilation tools and test runners, which frequently include ANSI escape sequences—special byte sequences used by terminals to control colors, cursor position, and hyperlinks. The OSC 8 standard extends this to embed clickable hyperlinks directly in terminal output. Libraries like ansi2html.py convert these escape sequences into HTML so they can be displayed correctly in a browser, but converting untrusted text into HTML inherently risks XSS if user-controlled bytes are not properly escaped or filtered.

Quanta Magazine has published an in-depth feature examining the holographic principle and what its growing empirical and theoretical support implies for our understanding of gravity, spacetime, and the fundamental nature of reality. If gravity is genuinely holographic, it would revolutionize physics by suggesting that our three-dimensional universe is a projection of information encoded on a distant two-dimensional surface, directly impacting the quest for a theory of quantum gravity and our conception of physical reality. The holographic principle asserts that the description of a volume of space can be encoded on a lower-dimensional boundary, a concept originally derived from black hole thermodynamics and now central to approaches like the AdS/CFT correspondence in string theory.

rss · Hacker News \(热门\) · Sep 25, 15:31

**Background**: The holographic principle originated from efforts to reconcile general relativity with quantum mechanics, particularly through the study of black hole entropy, which suggested that the information content of a black hole scales with its surface area rather than its volume. This led physicists such as Gerard &\#x27;t Hooft and Leonard Susskind to propose that all information in a region of space could be encoded on its boundary. The concept gained rigorous mathematical formulation through the AdS/CFT correspondence developed by Juan Maldacena in 1997, establishing a duality between a higher-dimensional gravitational theory and a lower-dimensional quantum field theory. Researchers continue to test these ideas because a working theory of quantum gravity remains one of the biggest unsolved problems in physics.

## [First Radio Signals Detected From an Exoplanet](https://www.wired.com/story/scientists-detect-radio-signals-from-exoplanet-for-first-time-in-history/) ⭐️ 6.0/10

Astronomers have detected radio signals originating from an exoplanet for the first time in history. The emission is attributed to magnetic activity, specifically electron cyclotron maser radiation linked to auroral processes, rather than any sign of extraterrestrial intelligence. This breakthrough represents a milestone in exoplanetary science, providing the first direct method to measure an exoplanet&\#x27;s magnetic field from afar. It opens a new observational window for studying the internal composition, dynamics, and habitability conditions of distant worlds. The likely detection is associated with the exoplanet Tau Boötis b, and the radio emission is produced via electron cyclotron maser \(ECM\) emission in the 10–40 MHz band. This phenomenon is analogous to Jupiter&\#x27;s auroral radio emissions, and the detection still requires further confirmation to be considered definitive.

rss · Wired · Sep 24, 09:00

**Background**: Exoplanets are planets orbiting stars outside our Solar System. Radio astronomy is a branch of observational astronomy that studies celestial objects by measuring the radio waves they emit. Some planets in our Solar System, notably Jupiter, produce strong radio emissions caused by their magnetic fields interacting with charged particles, a process related to auroras. Detecting similar emissions from exoplanets would allow astronomers to directly measure their magnetic fields, which are otherwise extremely difficult to characterize and which play a key role in protecting a planet&\#x27;s atmosphere from stellar radiation.

## [Debugging Email Spam: SPF/DKIM/DMARC Alignment in Node.js](https://dev.to/calderhayes9638/mail-going-to-spam-after-spf-dkim-dmarc-setup-with-nodejs-alignment-debugging-1e41) ⭐️ 6.0/10

A debugging guide explains that emails can still land in spam even when SPF, DKIM, and DMARC all return green, because DMARC alignment requires the visible From header domain to match either the SPF-authenticated domain or the DKIM d= domain. The article advocates treating each outgoing message as a ledger entry, capturing envelope sender, header From, DKIM domain, selector, sending IP, and the receiver&\#x27;s Authentication-Results. In multi-tenant marketplace scenarios where each seller customizes their sending domain, a platform may sign messages with its own shared DKIM domain while displaying a seller&\#x27;s From address, causing silent DMARC misalignment and spam folder placement. Without an audit trail of per-message authentication evidence, developers waste time chasing DNS configuration when the actual problem lies in domain identity relationships. The article distinguishes between relaxed alignment \(organizational-domain matching per RFC 7489\) and strict alignment \(exact match\), noting that a forwarded message can change the alignment outcome. It provides a Go struct example for a DeliveryEvidence record with fields including MessageID, EnvelopeFrom, HeaderFrom, SPFDomain, DKIMDomain, and DMARCResult, designed to be stored in Postgres or an append-only log.

rss · Dev.to · Sep 25, 19:41

**Background**: SPF \(Sender Policy Framework\) authorizes which IP addresses can send mail for a domain by checking the envelope sender \(Return-Path\). DKIM \(DomainKeys Identified Mail\) adds a cryptographic signature to the message header, verified against a public key published in DNS. DMARC \(Domain-based Message Authentication, Reporting, and Conformance\) ties these together by requiring that either the SPF-authenticated domain or the DKIM d= domain aligns with the visible From header domain \(RFC 5322.From\). Without this alignment, a recipient MTA has no cryptographic proof that the displayed sender actually authorized the message, leading to spam folder placement.
