## [用 Rust 查询引擎让 Postgres 分析查询提速 300 倍](https://malisper.me/how-we-made-postgres-hundreds-of-times-faster-the-query-engine/) ⭐️ 8.0/10

作者构建了一个名为 pgrust 的基于 Rust 的 Postgres 查询引擎，通过批处理（将多行数据成组处理而非逐行处理）、算子融合（合并多个查询算子以避免中间结果的物化）和 SIMD 向量化（利用 CPU 向量指令并行处理多个数据点）三项关键优化技术，使分析查询实现了高达 300 倍的加速。该项目是对 Postgres 查询引擎的部分重写，目前正通过形式化证明和差异性模糊测试来重点验证正确性。 这项工作打破了人们长期以来的固有认知，即 Postgres 无法与专门的分析型数据库（OLAP 系统）竞争。如果该方案日趋成熟并被广泛采用，将极大拓展 Postgres 在分析场景下的应用范围，减少对独立数据仓库的需求。同时，它还证明了自适应查询规划（adaptive query planning）在主流数据库中的可行性——而这正是官方 Postgres 团队历来不愿实现的特性。 作者明确表示正确性是项目的首要优先级：已形式化证明 pgrust 与 Postgres 中超过 1,000 个面向用户的函数行为完全一致，并以差异性模糊测试作为补充验证。然而，正如评论者所指出的，pgrust 只是部分重写，并非即插即用的替代品，并且缺乏官方 Postgres 项目所具备的长期维护保障、生态系统支持以及相应的信任度。

hackernews · Hacker News \(热门\) · 8月7日 11:00 · [社区讨论](https://news.ycombinator.com/item?id=49208535)

**背景**: PostgreSQL（通常简称为 Postgres）是一款被广泛使用的开源关系型数据库，传统上主要针对事务型工作负载（OLTP）进行优化，而非分析型查询（OLAP）。分析型查询通常需要扫描大量数据并进行聚合、过滤和连接操作——这类工作历来在 ClickHouse、DuckDB 等列式数据库中要快得多。SIMD（单指令多数据，Single Instruction, Multiple Data）是 CPU 的一项特性，能够对多个数据值同时执行同一条指令，对于分析场景中常见的重复数值运算极为高效。批处理和算子融合是两项成熟的数据库优化技术：批处理将多行数据一并处理（类似于 SQL Server 的批处理模式执行），而算子融合则将多个算子合并为单次扫描执行，避免产生和读取中间结果集。自适应查询规划是指数据库在查询执行过程中根据实际观测到的数据统计信息动态调整执行策略的能力，而不是在执行前就固定执行计划。
