## [Anthropic 发布 Claude Sonnet 5.5：更快、更便宜，并上线免费版](https://simonwillison.net/2026/Sep/28/claude-sonnet-5-5/) ⭐️ 8.0/10

Anthropic 发布了 Claude Sonnet 5.5，运行速度提升超过 30%，成本降低高达 30%，并在基准测试中全面超越 Sonnet 5。该模型现已为 claude.ai 的免费版提供支持，取代了此前的免费模型。Simon Willison 的实测发现 Sonnet 5.5 与 Opus 5.5 共享同一个 &quot;max&quot; 思维强度模式下的已知 Bug——模型会耗尽 128,000 个 token 的推理预算却无法产出结果。 Sonnet 5.5 大幅缩小了与旗舰模型 Opus 5.5 的能力差距，尤其在编程任务上，使得 Anthropic 免费版的整体能力显著强于由 Luna 5.6 驱动的 OpenAI ChatGPT 免费版。速度、成本与基准成绩的多重提升加剧了中端大模型市场的竞争压力，也体现了 Anthropic 将强模型下放至免费用户的战略。 API 定价与 Sonnet 5 保持一致，因此成本下降来源于模型效率提升而非降价。在 Willison 的测试中，&quot;xhigh&quot; 思维强度以 5.74 美分、41 秒成功生成了一张正确的鹈鹕骑自行车的 SVG 图，但 &quot;max&quot; 模式则花掉 1.28 美元后仍然失败。Anthropic 还确认 Haiku 5.5 将于&quot;未来几周内&quot;推出，届时整个产品线都将升级到 5.5 版本。

rss · Simon Willison \(AI 跨行业洞察\) · 9月28日 22:07

**背景**: Anthropic 的 Claude 模型家族按层级划分——Haiku（小型/快速）、Sonnet（中端）和 Opus（旗舰），每个层级通常会通过版本迭代进行更新。Extended thinking（扩展思维）是 Anthropic API 的一项功能，模型在回答前会先生成一段内部的思维链（Chain-of-Thought），并支持 &quot;medium&quot;、&quot;high&quot;、&quot;xhigh&quot; 和 &quot;max&quot; 等可配置的强度档位。&quot;鹈鹕骑自行车&quot;的 SVG 提示已经成为社区衡量大模型视觉推理与编程任务性价比的非正式基准。

本文重新审视了幂等键的设计，超越了教科书的定义，区分了两种重试场景：进行中的请求（应被告知处理正在进行）和已完成的请求（必须返回从存储快照中重放的原始结果）。文章展示了一种检查后写入的模式，它有意避免使用前置锁，而是依靠数据库级别的唯一约束来解决两个并发请求同时查不到已存在记录时的竞争问题。 如果实现错误，就会出现重复扣费、重复预订座位或重复下单等问题——这恰恰是幂等键本应避免的故障。在并发负载下的正确行为，是区分教科书式 API 和能在生产分布式系统中经受住真实重试、超时和竞争条件的 API 的关键。 该实现使用 \`findExisting\` 然后 \`createPendingSettlement\` 的流程，通过捕获 \`DataAccessException\` 来从失败的竞争中恢复，方法是重新读取胜出的记录。一个值得注意的细节是，在 Postgres 下，相同的竞争条件有时表现为干净的唯一约束冲突，有时表现为竞争索引操作之间的死锁，这意味着恢复代码必须同时处理这两种失败模式。

rss · Dev.to · 9月29日 22:42

**背景**: 幂等键是客户端生成的唯一标识符，附加在具有副作用的请求上（如支付或订单创建），以便服务器能够识别并去重重试，而不是将同一操作处理两次。经典的教科书式保证是重复请求返回原始结果，但在并发负载下，这种保证要难维护得多。当两个重试同时到达，或者客户端超时并在第一个请求仍在执行时发起第二次尝试时，两者都可能错过缓存检查并都尝试执行底层操作，这正是本文要解决的核心场景。
