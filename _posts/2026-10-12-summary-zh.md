## [WiFi 7 路由器被改造为 320 Msps 软件定义无线电接收器](https://github.com/h0m3us3r/w1700k-sdr) ⭐️ 8.0/10

开发者 h0m3us3r 在 GitHub 上发布了自定义固件，可将 Gemtek W1700K WiFi 7 路由器变成宽带软件定义无线电接收器，在 2.4/5/6 GHz 频段上以最高 320 Msps 的速率采集原始 14 位 IQ 数据。路由器的 MediaTek MT7996 射频芯片通过 Airoha AN7581 SoC 经 10GbE 将采样流传输至 Linux 主机，在浏览器中实时显示频谱和瀑布图。 具有类似采样率和 5 GHz 覆盖范围商用 SDR 接收器通常要贵出几个数量级，因此这一破解方案大幅降低了高性能射频实验、研究和教育的门槛。它也展示了消费级 WiFi 7 芯片组的潜在能力远超其设计用途，引发了关于如何重新利用通用射频硬件的更广泛讨论。 该接收器并非真正的全频段（DC-to-daylight）SDR，而是利用 MediaTek MT7996 原生射频前端围绕 2.4/5/6 GHz 频段进行调谐。以 320 Msps 速率无丢包传输需要路由器的 10GbE 链路支持，浏览器界面意味着主机端无需安装任何专用 SDR 软件。

hackernews · Hacker News \(热门\) · 10月12日 12:41 · [社区讨论](https://news.ycombinator.com/item?id=50055593)

**背景**: 软件定义无线电（SDR）用数字采样和软件处理取代传统的模拟射频电路，使单台硬件能够在宽频率范围内调谐并支持多种协议。要在 5 GHz 等微波频段捕获宽带信号，需要极高的采样率（每秒数亿次采样），此类 ADC 通常价格昂贵。MediaTek MT7996 等 WiFi 7（802.11be）芯片组本身已包含能跨 2.4、5 和 6 GHz 频段捕获宽带信号的快速 ADC 和 DSP 模块，用于正常的 Wi-Fi 工作；这一破解方案只不过替换了厂商固件，将原始采样流暴露给主机 PC。

## [通过 Flask Pickle 反序列化在 Google 发现价值 9 万美元的 RCE 漏洞](https://simonkoeck.com/writeups/google-devsite-flask-session-pickle-rce) ⭐️ 8.0/10

安全研究员 Simon Koeck 发布了一份详细的技术报告，披露他在 Google devsite 中发现的远程代码执行（RCE）漏洞，该漏洞获得了 9 万美元的漏洞赏金奖励。该漏洞利用了 Flask 会话 Cookie 使用 Python pickle 模块进行的不安全反序列化。 此案例表明，即使是像 Google 这样资源丰富的组织，也可能遭受 Python Web 框架中不安全反序列化漏洞的攻击。高额赏金反映了该漏洞的严重性——Google 基础设施上完整的未认证 RCE——并为所有使用 Flask 和基于 pickle 的会话处理机制的团队敲响了警钟。 该利用链依赖于 Flask 默认的会话 Cookie 格式，该格式通过 pickle 序列化会话数据并使用密钥签名（而非加密）。如果签名密钥较弱或泄露，攻击者可以伪造一个包含恶意 pickle 负载的 Cookie，该 Cookie 在服务器上反序列化时将执行任意代码。Python 的 pickle 模块本质上不应用于不受信任的数据，因为反序列化过程可以通过 \_\_reduce\_\_ 调用任意可执行对象。

rss · Lobsters \(技术社区\) · 10月12日 14:40

**背景**: Flask 是一个流行的轻量级 Python Web 框架，默认使用客户端签名 Cookie 来存储会话数据。为了序列化会话内容，Flask 依赖于 pickle 模块，而该模块在反序列化过程中可以执行任意代码——这是 Python 安全社区反复强调的一个已知危险。Google 运营着一个 Bug Hunters 漏洞奖励计划，对报告其产品和基础设施中符合条件漏洞的研究人员给予奖励。
