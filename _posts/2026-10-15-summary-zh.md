## [AdFection：经由定向广告投递的零点击间谍软件](https://citizenlab.ca/research/how-discover-tech-turned-targeted-ads-into-a-pipeline-for-spyware/) ⭐️ 8.0/10

Citizen Lab 发布了一项名为 &quot;AdFection&quot; 的间谍软件活动的技术证据，其中一家以色列广告公司（Discover-Tech）投放了数百万在线广告，利用浏览器漏洞向目标设备投递零点击商业间谍软件。这是首次有记录的商业间谍软件通过全球广告网络进行分发的事件。 这一发现从根本上挑战了&quot;仅仅浏览网页就是安全的&quot;这一假设，将整个程序化广告生态系统变成了国家级监控的潜在攻击向量。它影响到普通用户、记者、异见人士和企业，并引发了关于广告网络问责制和监管框架的紧迫问题。 该攻击利用了在线广告的供应链，恶意代码被注入到合法网站和应用自动投放的广告中，整个过程无需用户交互。Citizen Lab 的报告包含针对广告网络、监管机构和终端用户的详细建议，并将在线广告定性为一场网络安全和隐私危机。

hackernews · Hacker News \(热门\) · 10月15日 10:43 · [社区讨论](https://news.ycombinator.com/item?id=50101813)

**背景**: 零点击间谍软件是指无需用户任何操作——无需点击链接、无需打开文件——即可入侵设备的恶意软件。以往的案例包括 NSO 集团的 Pegasus，它利用了 iMessage 等应用中的漏洞。程序化广告是一个自动化系统，网站和应用上的广告位通过实时竞价被填充，通常涉及复杂的中介链条——这种结构使得很难审计最终在用户设备上实际运行的代码。Citizen Lab 是多伦多大学 Munk 学院下设的研究小组，以调查国家支持的监控活动而闻名。

## [Epic Games 为 Linux 带来原生反作弊支持](https://onlineservices.epicgames.com/news/introducing-easy-anti-cheat-linux-v2) ⭐️ 8.0/10

反作弊长期以来一直是阻止许多热门多人游戏在 Linux 和 Proton 上运行的最大障碍，迫使 Steam Deck 和 Linux 桌面用户为了竞技游戏不得不退回 Windows。原生的 EAC 支持将大量此类游戏从「不可运行」名单中移除，进一步巩固了 Linux 作为主流游戏平台的地位。 EAC Linux v2 以原生方式在 Linux 上运行，而非依赖兼容层；不过内核级反作弊方案在开源社区中仍然存在信任和安全方面的担忧。现有的基于 Proton 的变通方案和用户态实现，对于选择采用原生方案的游戏仍将具有参考价值。

rss · Lobsters \(技术社区\) · 10月14日 15:13

**背景**: Easy Anti-Cheat 是 PC 游戏领域部署最广泛的反作弊系统之一，被包括 Fortnite、Apex Legends 等在内的数百款游戏所采用。Linux 游戏体验在很大程度上依赖 Valve 的 Proton——这是一个基于 Wine 构建的兼容层，用于将 Windows 调用转换过来，使仅限 Windows 的游戏可以在 Linux 上运行；但 Proton 无法复刻 Windows 特有的内核级反作弊驱动，这就是为什么许多多人游戏在 Linux 或 Steam Deck 上即使游戏逻辑完全正常也无法启动的原因。内核级反作弊运行在操作系统的 Ring 0 层级，能深入监控系统，但也因此引发了隐私和安全方面的担忧，使得 Linux 发行版和开源社区对此类支持一向持谨慎态度。

## [GitLab 警告存在最高严重级别的代码执行漏洞](https://www.bleepingcomputer.com/news/security/gitlab-warns-of-max-severity-rce-flaw-in-regex-compiler-engine/) ⭐️ 8.0/10

GitLab 披露了其正则表达式编译引擎中存在一个最高严重级别（CVSS 10.0）的远程代码执行漏洞，编号为 CVE-2026-97229，影响 GitLab CE 和 EE 自托管实例。该缺陷存在于 GitLab 编译管道配置中正则表达式的方式中，未认证的攻击者可利用它在服务器上执行任意代码。 GitLab 被开发团队广泛用于托管源代码仓库和运行 CI/CD 管道，因此漏洞被利用可能暴露专有源代码、管道密钥以及生产基础设施。由于该漏洞可在自托管实例上无需认证即可被利用，每个运行自有 GitLab 服务器的组织在打补丁之前都面临直接风险。 该漏洞专门针对 GitLab 在 .gitlab-ci.yml 等管道配置文件中处理正则表达式的方式，GitLab 14.9 之前的版本使用的是 Onigmo 正则引擎，之后迁移到了 RE2。最近还披露了另一个 GitLab EE 的 RCE 漏洞 CVE-2026-88765，表明存在一系列相关的正则表达式引擎安全问题。

rss · Lobsters \(技术社区\) · 10月14日 15:55

**背景**: GitLab 是一个将源代码托管、问题跟踪和 CI/CD 管道执行整合到一个应用程序中的 DevOps 平台，同时提供托管服务（GitLab.com）和自托管产品。CI/CD 管道通过 YAML 文件配置，支持使用正则表达式来定义规则和条件，以确定作业何时运行。由于管道通常可以访问密钥、部署凭证以及敏感的构建环境，因此管道处理层中的任何代码执行缺陷都被视为严重问题。

## [静态扫描器在加载前捕获 ONNX external\_data 路径穿越漏洞](https://dev.to/munimv2/statically-catching-onnx-externaldata-path-traversal-before-a-model-loads-ic1) ⭐️ 6.0/10

**背景**: ONNX（Open Neural Network Exchange，开放神经网络交换格式）是一种基于 Google protobuf 的可移植模型格式，常用于在 PyTorch、TensorFlow 以及 ONNX Runtime、\`tract\` 等推理运行时之间传递训练好的模型。当某个张量过大而无法内联时，模型会将其标记为 \`data\_location: EXTERNAL\`，并通过 \`external\_data\[\].location\` 指向一个同级文件，ONNX 规范要求该路径必须是模型目录内的相对路径。如果加载器仅仅是简单地把这个字符串拼接到模型目录后再打开，就会继承经典的路径穿越漏洞（CWE-22），攻击者可以利用 \`..\`、绝对路径、URL scheme、控制字符或 Windows 反斜杠逃逸出预期目录。
