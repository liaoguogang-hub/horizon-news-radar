## [Brown University Explores Async/Await Design Space](https://cel.cs.brown.edu/blog/design-space-async-await/) ⭐️ 8.0/10

Brown University&\#x27;s CEL \(Programming Languages, Compilers, and Environments\) lab has published an academic blog post exploring the design space of async/await, systematically analyzing the trade-offs and design decisions involved in implementing this concurrency paradigm. Async/await is one of the most widely adopted concurrency paradigms across modern languages including Rust, JavaScript, Python, and C\#, yet fundamental design questions remain contested. This academic analysis provides valuable guidance for language designers and systems engineers making decisions about future concurrency primitives. The blog adopts a design space analysis methodology, a semiformal approach that uses Questions, Options, and Criteria \(QOC\) to represent design rationale around software artifacts. This allows systematic comparison of how different languages occupy distinct regions of the async/await design space.

rss · Lobsters \(技术社区\) · Sep 9, 15:22

**Background**: Async/await is a syntactic construct for managing asynchronous operations that take time to complete without requiring constant attention from the CPU, such as network requests or file I/O. While the runtime mechanics differ across languages—JavaScript runs async/await on a single-threaded event loop, while Rust requires explicit composition for concurrent execution—the core concept enables developers to write non-blocking code that resembles synchronous code. Design space analysis is a well-established methodology in programming language research for mapping out the multidimensional trade-offs between competing design choices.

## [NVIDIA Launches CUDA Rust Support with Two GPU Kernel Tracks](https://developer.nvidia.com/blog/introducing-cuda-rust-two-tracks-for-writing-gpu-kernels/) ⭐️ 8.0/10

NVIDIA has announced CUDA Rust support, offering two distinct tracks for writing GPU kernels in Rust: cuda-oxide, a custom rustc codegen backend that compiles SIMT-style GPU kernels directly to PTX using the Pliron IR framework and LLVM, and cutile-rs, which enables Tile-based GPU programming in stable Rust. This announcement expands GPU programming beyond the long-standing C/C++ monopoly, allowing Rust systems engineers to write GPU kernels natively without learning template-heavy CUDA C++. It broadens the talent pool for kernel development—one of the tightest labor markets in AI infrastructure—and brings Rust&\#x27;s memory safety guarantees to high-performance GPU computing. The two tracks mirror CUDA&\#x27;s own dual programming paradigms: SIMT \(Single Instruction, Multiple Threads\) for fine-grained thread-level control, and Tile-based programming for higher-level data-parallel abstractions. Kernels are compiled directly to PTX rather than wrapping existing C/C++ code, and cuda-oxide requires a custom rustc backend while cutile-rs works with stable Rust.

rss · Lobsters \(技术社区\) · Sep 9, 13:21

**Background**: A GPU kernel is a function that runs on a GPU, executing computations in parallel across thousands of threads simultaneously. CUDA \(Compute Unified Device Architecture\) is NVIDIA&\#x27;s parallel computing platform that has historically relied on C/C++ as its primary programming language, with PTX \(Parallel Thread Execution\) serving as an intermediate instruction set that gets compiled for specific GPU hardware. Rust is a modern systems programming language prized for its memory safety guarantees and zero-cost abstractions, but until now lacked first-class tooling for writing GPU kernels natively. Tile-based programming is a newer abstraction that lets developers express data-parallel work over tiles \(blocks of data\) rather than managing individual threads manually.

The Lancet has published a comprehensive review synthesizing current evidence on the health effects of wildfire smoke exposure, highlighting key research gaps such as long-term health effects, interactions with pre-existing conditions, and health disparities, and outlining future challenges in the context of climate change. With wildfires increasing in frequency and scale worldwide due to climate change, understanding the full health impact of wildfire smoke is critical for protecting vulnerable populations and shaping public health policy, mitigation strategies, and emergency response efforts. Wildfire smoke is particularly toxic due to its complex mixture of combustion products; fine particulate matter \(PM2.5\) makes up approximately 90% of total particle mass emitted by wildfires and can travel far downwind, posing health risks even to populations far from the fire source.

rss · The Lancet · 最新文章 · Sep 8, 22:30

**Background**: Wildfire smoke contains a complex mixture of pollutants, with fine particulate matter \(PM2.5\)—particles 2.5 micrometers or smaller in diameter—being the most dangerous component due to its ability to penetrate deep into the lungs and enter the bloodstream. Epidemiological studies have linked wildfire smoke exposure to both acute effects such as respiratory irritation and exacerbation of asthma, as well as potential long-term effects including cardiovascular disease and lung function decline in children. However, estimating the causal health effects of wildfire smoke remains methodologically challenging because exposures are episodic, co-occur with other environmental stressors, and vary in composition depending on the materials burned.

## [First-in-human inhaled siRNA trial targets RAGE for lung inflammation](https://www.nature.com/articles/s41591-026-04607-z) ⭐️ 8.0/10

A randomized first-in-human clinical trial demonstrated that an inhaled siRNA therapy directed against the receptor for advanced glycation end-products \(RAGE\) was safe and well tolerated. The treatment successfully reduced RAGE levels in both serum and bronchoalveolar lavage fluid, confirming target engagement in the lung epithelium. This trial represents a major milestone for lung-targeted RNA therapeutics, demonstrating for the first time that inhaled siRNA can achieve meaningful gene silencing in human lungs. It opens a new therapeutic avenue for pulmonary inflammatory diseases such as COPD, asthma, and pulmonary fibrosis, where RAGE plays a key pathogenic role. The siRNA was specifically designed for lung-epithelium targeting via inhalation, overcoming the well-known instability of siRNA during systemic delivery. Reductions in RAGE were measured in both systemic circulation \(serum\) and locally \(bronchoalveolar lavage fluid\), providing dual evidence of target knockdown.

rss · Nature Medicine · Sep 9, 00:00

**Background**: Small interfering RNA \(siRNA\) molecules silence specific genes by guiding sequence-dependent cleavage of target messenger RNAs within the RNA interference pathway. RAGE \(receptor for advanced glycation end-products\) is a pattern recognition receptor implicated in chronic inflammation and tissue damage, particularly in pulmonary diseases. Because siRNA is unstable in vivo, inhaled formulations are being developed to deliver these molecules directly to the lungs, maximizing local efficacy while minimizing systemic exposure.

**Background**: GNU Radio is a free and open-source software development toolkit originally built for use with software-defined radios \(SDRs\) and simulating wireless communications; it lets users assemble signal processing blocks graphically into flowgraphs. Software-defined radio replaces traditional hardware-based radio components with programmable digital processing, and tools like the popular RTL-SDR dongles have made it a widespread hobbyist activity. Combining these, running GNU Radio in the browser means users can experiment with real signal processing pipelines without installing Python libraries, drivers, or hardware-specific toolchains.

## [nginx Silently Rejects HTTP QUERY Method via limit\_except](https://dev.to/alexgeorgiev17/nginxs-limitexcept-block-silently-rejects-the-new-http-query-method-1gcg) ⭐️ 7.0/10

A hands-on investigation reveals that nginx&\#x27;s \`limit\_except\` directive silently drops the new HTTP QUERY method defined in RFC 10008, even though curl sends the method correctly and FastAPI handles it without issue. The author tested nginx 1.24.0, Caddy 2.11.4, Traefik 3.7.10, and Django 6.1.1 behind a FastAPI 0.141.1 backend on a DigitalOcean droplet running Ubuntu 24.04. Because QUERY is intended to replace the widespread \`POST /search\` pattern—where GET cannot carry a complex filter body—any infrastructure layer that silently drops it will break API designs built on the new standard without giving operators any visible error. Web teams adopting QUERY need to know that nginx&\#x27;s behavior is an undocumented compatibility footgun, not just a missing feature. The \`limit\_except\` block in nginx whitelists methods by name; since QUERY is not enumerated, requests are rejected before reaching the upstream, without a 405 or any explicit error response. curl 8.5.0 requires no special flag to send QUERY with a JSON body, and FastAPI on Starlette 1.6.0 dispatches the method correctly when registered, isolating the problem to nginx&\#x27;s access-control layer.

rss · Dev.to · Sep 9, 21:11

**Background**: RFC 10008, published as a Proposed Standard in June, defines QUERY as a new HTTP method that is both safe and idempotent—meaning it should not change server state and can be repeated without side effects—yet still carries a request body like POST. This fills a long-standing gap: GET is safe but cannot carry a real body, while POST carries a body but is neither safe nor idempotent. The \`limit\_except\` directive in nginx is a core-module feature used inside a \`location\` block to allowlist specific HTTP methods and apply access rules \(such as authentication\) to anything else; methods not on the allowlist are rejected. Because nginx uses a hardcoded list of recognized method names in this directive, newly standardized methods like QUERY fall through the cracks.
