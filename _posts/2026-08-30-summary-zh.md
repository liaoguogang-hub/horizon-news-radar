## [QubesOS 复制到虚拟机错误报告通道存在任意代码执行漏洞](https://www.qubes-os.org/news/2026/08/29/qsb-118/) ⭐️ 8.0/10

QubesOS 披露了一个严重的任意代码执行漏洞（QSB-118），该漏洞可从 Dom0 通过 \`qvm-copy-to-vm\` 的错误报告回传通道被利用。该缺陷源于 Dom0 错误报告函数中使用了 \`system\(\)\` 调用，攻击者可借此执行任意命令。 在 QubesOS 基于 Xen 的架构中，Dom0 是拥有最高权限的域，在其中实现任意代码执行后果极其严重，可能破坏整个系统的隔离保障。此次漏洞尤其值得关注，因为它攻击的是 QubesOS 的核心功能——虚拟机之间的安全文件复制，动摇了用户对该操作系统安全模型的信任。 只有 Dom0 版本的 \`qvm-copy-to-vm\` 受影响；虚拟机之间复制的版本使用了不同的错误报告函数，不会调用 \`system\(\)\`。由于 Qubes 的最佳实践不鼓励在 Dom0 中执行常规工作，实际的攻击面比最初看起来要小，但对于任何依赖 Dom0 复制操作的工作流来说仍然严重。

hackernews · Hacker News \(热门\) · 8月30日 08:51 · [社区讨论](https://news.ycombinator.com/item?id=49496918)

**背景**: QubesOS 是一个以安全为导向的操作系统，利用 Xen 虚拟机监控程序将不同活动隔离到独立的虚拟机（域）中。Dom0（Domain 0）是虚拟机监控程序在启动时创建的第一个拥有最高权限的域，负责管理所有非特权域（DomU）并拥有直接硬件访问权限。\`qvm-copy-to-vm\` 是 QubesOS 的核心工具，用于在虚拟机之间安全传输文件，其安全性对操作系统的隔离理念至关重要。受影响的代码位于 Dom0 端的错误报告路径中，未净化的输入被传递给 \`system\(\)\`，构成了一个典型的命令注入向量。

## [连续扩散语言模型：超越自回归的新范式](https://sander.ai/2026/08/24/continuous-dlms.html) ⭐️ 8.0/10

Sander Dieleman 发布了一篇深入探讨连续扩散语言模型（CDLM）的文章，该方法在连续向量空间中进行语言建模，而非在离散 token 上操作，区别于标准的自回归范式。 如果 CDLM 能证明其与自回归大语言模型相媲美，可能会改变语言模型的训练和采样方式，在可控性、并行生成以及双向上下文利用方面带来潜在优势，并可能影响 DeepMind 等实验室及整个行业的未来架构设计。 该博客文章由 DeepMind 知名研究员 Sander Dieleman 撰写，发布于 2026 年 8 月 24 日。其核心技术思想是将此前主要应用于图像生成的扩散方法扩展到语言的连续嵌入空间，从而避免了基于 token 的扩散方法所需的离散化步骤。

rss · Hacker News \(热门\) · 8月30日 20:46

**背景**: 目前大多数主流语言模型（如 GPT 系列大语言模型）都是自回归的：每次生成一个离散 token，每个 token 都以之前所有已生成的 token 为条件。扩散模型则起源于图像生成领域（如 Stable Diffusion），它通过学习对随机向量进行迭代去噪来生成连贯的输出，天然支持并行和双向生成。连续扩散进一步将这一思路推广到连续向量空间，避免将输出量化为离散 token，从而保留更丰富的语义信息并简化建模流程。

**社区讨论**: 该文章在 Hacker News 上引发了高度关注（讨论帖 id 49502611），表明社区对自回归大语言模型之外的替代架构有浓厚兴趣，但提供的内容中未包含具体评论内容。

## [Zig 为 ArrayList 添加指针稳定性支持](https://ziglang.org/devlog/2026/#2026-08-27) ⭐️ 7.0/10

Zig 官方开发日志宣布为 ArrayList 提供指针稳定性保证，从而允许对元素进行安全的并发访问。这项期待已久的增强功能由 GitHub issue \#19326 追踪并通过 PR \#22988 实现，对标准库 ArrayList 的 API 进行了调整。 指针稳定性是系统程序员构建实体组件系统（ECS）、图结构和缓存等数据结构时的关键特性，因为这些场景都需要稳定的引用。这一改进使 Zig 的 ArrayList 更接近专用指针稳定容器的能力，也消除了此前迫使用户放弃标准 ArrayList 的一个常见痛点。 该实现通过安全锁（safety locks）进行门控，意味着指针稳定性 API 大概率仅在 debug/safe 构建模式下可用，以防止未定义行为。相关工作也在通过 issue \#19327 为 MultiArrayList 进行，表明 Zig 团队正在更广泛地推进各类容器的指针稳定性支持。

rss · Hacker News \(热门\) · 8月30日 14:41

**背景**: 指针稳定性是指存储在动态容器中元素的指针或引用在容器被修改（例如插入或删除操作导致内存重定位）之后仍然保持有效。传统可增长数组（如 Zig 的 ArrayList）在重新分配扩容时通常会使已有的指针失效。许多高级数据结构——例如 ECS 架构中的稀疏集合、Linux 内核中的 BPF 图以及各种缓存实现——都依赖指针稳定性来高效运行，避免代价高昂的重新哈希或指针重定向。

## [Rust 团队启动函数重载实验](https://blog.rust-lang.org/inside-rust/2026/08/19/overloading-experiment/) ⭐️ 7.0/10

Rust 语言团队在官方 Inside Rust 博客上发布了一篇文章，呼吁社区对函数重载进行实验。该倡议邀请社区成员探索、原型设计并就重载特性如何融入语言提供反馈。 函数重载一直是 Rust 社区中长期争论的特性，这次官方呼吁表明语言团队正在认真探索是否以及如何添加该特性。其结果可能改变 Rust 的 API 易用性，并影响各种库和框架向用户公开功能的方式。 Rust 的变更通常遵循 RFC（征求意见）流程，这意味着本次实验的任何成果可能都需要被正式化为一份 RFC。社区中已有的实验——例如基于 trait 的分派模式以及第三方概念验证仓库——表明在官方语言团队之外，重载的替代方案已经被探索过。
