## [Go 新增实验性平台无关 SIMD 支持](https://go.dev/blog/simd-experiment) ⭐️ 8.0/10

Go 团队宣布推出一项实验性的平台无关 SIMD 包，相比标量 Go 代码可实现约 5 倍加速，同时仅比架构特定的内建函数慢约 11%。新 API 允许开发者编写可在不同架构上编译的向量化代码，无需编写平台特定的汇编。 这大大降低了在 Go 中进行高性能计算的门槛，无需 CGO 或手写汇编即可利用 CPU 的 SIMD 指令。它使得机器学习推理、图像处理和加密等工作负载能够完全在纯 Go 中实现具有竞争力的性能。 该包通过每个向量类型上的 ToArch\(\) 转换方法支持与架构特定 SIMD 之间的转换。值得注意的是，正如讨论中的实践者所强调的那样，该设计是首个能够处理 ARM SVE 和 RISC-V V 扩展等非固定宽度向量 ISA 的可移植 SIMD 方案。

hackernews · Hacker News \(热门\) · 9月25日 11:47 · [社区讨论](https://news.ycombinator.com/item?id=49843269)

**背景**: SIMD（单指令多数据）是一类并行计算方式，一条指令可以同时对多个数据点进行操作，现代 CPU 通过 SSE、AVX（x86）、NEON/SVE（ARM）以及 V 扩展（RISC-V）等指令集扩展提供该能力。传统上，利用 SIMD 需要依赖编译器自动向量化或编写平台特定的内建函数与汇编，两者都很繁琐且不可移植。近期可移植 SIMD 的工作包括 Rust 的 portable SIMD crate、Fearless SIMD 计划以及即将推出的 C++26 std::simd。

## [SourceHut 通过 ansi2html.py XSS 漏洞导致账户被接管](https://blog.arusekk.pl/posts/srht-account-takeover/) ⭐️ 8.0/10

在 SourceHut 用于将 ANSI 转义码渲染为 HTML 的 ansi2html.py 库（版本 1.7.0a0 至 1.9.3）中，发现了一个可蠕虫传播的跨站脚本（XSS）漏洞，编号为 CVE-2026-92973。该漏洞允许任何能够向 builds.sr.ht 任务日志注入文本的人，在查看该日志的任何用户（包括管理员）的浏览器中执行任意 JavaScript。 该漏洞尤为严重，因为它是可蠕虫传播的，仅通过查看恶意构建日志就能导致用户（包括管理员）账户被接管，可能影响整个平台的安全。它凸显了在任何 CI/CD 或构建日志渲染流程中正确清理终端转义序列的至关重要性，因为 ANSI/OSC 8 超链接支持引入了一个新的、容易被忽视的攻击面。 根本原因在于 OSC 8 超链接转义序列的清理不当，攻击者可以构造带有嵌入式 HTML 属性（例如 onfocus 处理器）的 href。该漏洞 CVSS 评分为 6.1（中等严重程度），不仅影响 SourceHut，还影响任何在受影响版本范围内使用 ansi2html 的其他项目或实例。

rss · Lobsters \(技术社区\) · 9月24日 20:38

**背景**: SourceHut 是一个开发者锻造平台，提供 Git 仓库、CI/CD 构建、邮件列表和缺陷跟踪，常被开源开发者用作 GitHub 的轻量级替代方案。CI/CD 构建日志通常包含编译工具和测试运行器的原始输出，其中经常包含 ANSI 转义序列——终端用来控制颜色、光标位置和超链接的特殊字节序列。OSC 8 标准进一步扩展了这一机制，允许在终端输出中直接嵌入可点击的超链接。像 ansi2html.py 这样的库将这些转义序列转换为 HTML，以便在浏览器中正确显示，但将不可信文本转换为 HTML 本身就存在 XSS 风险，除非对用户控制的字节进行正确的转义或过滤。
