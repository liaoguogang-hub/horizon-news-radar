## [OpenAI cuts GPT-5.6 prices up to 80% using AI-optimized inference](https://simonwillison.net/2026/Jul/30/luna-price-drop/#atom-everything) ⭐️ 9.0/10

OpenAI announced major price reductions for GPT-5.6 Terra \(20% drop\) and GPT-5.6 Luna \(80% drop\), with Luna now priced at $0.20 per million input tokens and $1.20 per million output tokens. The cost reductions were enabled by using GPT-5.6 Sol to autonomously rewrite and optimize production GPU kernels, including the model&\#x27;s inference forward pass, load balancing, and memory movement. Luna is now cheaper than Google&\#x27;s Gemini 3.1 Flash-Lite and roughly one-fifth the input cost of Anthropic&\#x27;s Claude Haiku 4.5, reshuffling the low-cost LLM market. More fundamentally, using one AI model to autonomously optimize the inference stack of another points toward a self-improving infrastructure loop that could drive sustained cost declines across the industry. GPT-5.6 Sol identified work that could be precomputed, avoided, or parallelized, and with Codex it autonomously rewrote production kernels written in Triton and Gluon—two open-source GPU programming languages maintained by OpenAI. These optimizations reduced end-to-end serving costs by 20%, which compounded with broader inference improvements to enable the 80% Luna price drop.

**Background**: An LLM inference &\#x27;forward pass&\#x27; is the computation that transforms input tokens into next-token predictions; even when individual operations are fast, excess GPU memory movement, synchronization, and inefficient data layouts can leave hardware idle and inflate serving costs. &\#x27;Kernels&\#x27; are the low-level GPU code that executes the mathematical operations underlying the model, and optimizing them typically requires specialized engineering effort. Triton and Gluon are open-source Python-based GPU programming languages that lower the barrier to writing high-performance AI kernels. Load balancing across multiple model replicas is also critical, since a single GPU instance cannot serve thousands of concurrent users.

## [PRISM2: Multimodal Pathology Foundation Model with Clinical Dialogue](https://www.nature.com/articles/s41591-026-04521-4) ⭐️ 9.0/10

Researchers have introduced PRISM2, a multimodal slide-level foundation model trained on 2.3 million whole-slide images and 14 million question-answer pairs derived from 700,000 pathology reports. Without any task-specific training, PRISM2 matched or exceeded the cancer-detection performance of clinical-grade products, published in Nature Medicine on July 31, 2026. This represents a major advance in computational pathology because it shows that a single general-purpose model can handle cancer detection and other pathology tasks without the costly process of retraining for each specific task. By aligning histology images with clinical diagnostic reasoning through dialogue supervision, PRISM2 could streamline cancer diagnosis workflows and make AI-assisted pathology more accessible. PRISM2 was developed by Paige in collaboration with Microsoft Research, with the QA pairs generated automatically from pathology reports to provide clinical dialogue supervision. The model aligns histomorphology \(the visual patterns in tissue\) with diagnostic reasoning, enabling generalist pathology AI without loss of performance on other tasks.

rss · Nature Medicine · Jul 31, 00:00

**Background**: A whole-slide image \(WSI\) is a high-resolution digitized scan of a pathology slide that pathologists examine to diagnose diseases such as cancer. Traditional computational pathology models are usually trained for a single task, such as detecting one type of tumor, requiring large labeled datasets for each new task. Foundation models are large AI models pre-trained on massive datasets that can later be adapted to many downstream tasks; PRISM2 is a slide-level foundation model that combines visual understanding of pathology images with language-based clinical dialogue, allowing it to learn diagnostic reasoning similar to how a pathologist reasons during case review.

## [Tailscale Details How Hugging Face Intrusion Bypassed Its Network](https://tailscale.com/blog/hugging-face-intrusion) ⭐️ 8.0/10

Tailscale published a transparent postmortem explaining how a leaked reusable Tailscale auth key from Hugging Face&\#x27;s compromised environment allowed an attacker to enroll 181 nodes into Hugging Face&\#x27;s tailnet over several days, receiving full CI-level access. No Tailscale vulnerability was exploited — the breach stemmed from the auth key being exposed in an environment file, but Tailscale acknowledges it failed to detect and alert on the anomalous node enrollment activity. This postmortem is a rare example of a security vendor openly taking accountability for a customer&\#x27;s breach even though their own software functioned as designed. It highlights a systemic gap in observability: mesh VPN tools like Tailscale provide powerful zero-trust networking but lack built-in alerting for sensitive actions like bulk node enrollment, leaving organizations blind when credentials leak. Tailscale is committing to ship new alerting features for node enrollment events, treating this as a product gap rather than a customer error. The reusable auth key — a feature designed for CI/CD automation — became the attacker&\#x27;s persistent foothold because it could be reused indefinitely from external sandboxes, and each newly enrolled node automatically received identity tags granting CI privileges.

hackernews · Hacker News \(热门\) · Jul 31, 19:03 · [Discussion](https://news.ycombinator.com/item?id=49127306)

**Background**: Tailscale is a mesh VPN service built on the WireGuard protocol that creates private encrypted networks called &\#x27;tailnets,&\#x27; where each device gets a stable IP address and identity. &\#x27;Auth keys&\#x27; are pre-authentication tokens that allow devices to join a tailnet automatically — particularly useful for CI/CD runners and ephemeral infrastructure. &\#x27;Reusable&\#x27; auth keys can be used multiple times to enroll many devices, which is convenient for automation but creates risk if the key is leaked, since anyone possessing it can join the network with whatever tags and permissions it carries.

## [GitHub Launches Stacked Pull Requests in Public Preview](https://github.blog/changelog/2026-07-30-stacked-pull-requests-are-now-in-public-preview/) ⭐️ 8.0/10

GitHub announced that stacked pull requests are now available in public preview, rolling out to all repositories over the coming days. The feature allows developers to organize dependent changes as an ordered hierarchy of smaller, independently reviewable pull requests. This addresses one of the most long-requested features in the GitHub community, significantly improving workflow productivity for teams managing large or complex changes. It reduces the friction of breaking monolithic PRs into manageable increments, enabling parallel review and faster iteration cycles. Stacked PRs present changes as discrete, ordered layers that build upon one another, allowing reviewers to examine focused increments instead of a single massive diff. GitHub also introduced the \`gh-stack\` CLI extension for use with GitHub Copilot, enabling a single-operation merge workflow across the entire stack.

rss · Lobsters \(技术社区\) · Jul 30, 16:52

**Background**: Stacked pull requests, also known as stacked diffs or stacked changes, are a workflow concept where a large feature is broken into a series of small, dependent changes that build on top of one another. Each PR in the stack represents a coherent, independently reviewable and mergeable unit. This approach is particularly valuable when changes are too large to review as a single diff, when intermediate steps need separate approval, or when parallel development across teams requires coordinated merging. Prior to this launch, developers typically relied on third-party tools like Graphite to manage stacked PR workflows on GitHub.

## [Max-Severity Exchange Flaw Exploited by Kremlin Hackers](https://arstechnica.com/security/2026/07/kremlin-hackers-are-exploiting-exchange-flaw-to-backdoor-unpatched-networks/) ⭐️ 8.0/10

Russian state-sponsored hackers are actively exploiting a maximum-severity vulnerability in Microsoft Exchange Server to deploy the OWAReaper backdoor on unpatched systems. The exploit grants persistent server access that survives credential rotation and disk re-imaging, making remediation significantly more difficult. This is critical for security teams managing on-premises Exchange infrastructure, as the persistence mechanisms mean that standard incident response procedures—changing passwords and re-imaging servers—are insufficient to evict the attackers. State-sponsored actors achieving this level of foothold can conduct long-term espionage, mailbox access, and lateral movement within enterprise and government networks. The attack uses a half-click exploit against Exchange Server and installs the OWAReaper backdoor targeting Outlook Web Access \(OWA\). Organizations in air-gapped or disconnected environments can apply mitigations using the Exchange On-Premises Mitigation Tool \(EOMT\) from an elevated Exchange Management Shell, while connected environments should use the Exchange Health Checker script to verify patch status.

rss · Ars Technica · Jul 30, 20:57

**Background**: Microsoft Exchange Server is an enterprise email and calendaring platform widely used by governments, corporations, and critical infrastructure operators. A zero-day vulnerability is a flaw that is exploited before the vendor has released a patch, leaving defenders with limited options beyond mitigations. Advanced Persistent Threats \(APTs\) are stealthy, state-sponsored hacking groups—such as Kremlin-linked APT29—that gain unauthorized access to networks and remain undetected for extended periods to conduct espionage. Persistence techniques refer to methods attackers use to maintain access to compromised systems even after defenders attempt to remove them, such as credential resets or full disk re-imaging.
