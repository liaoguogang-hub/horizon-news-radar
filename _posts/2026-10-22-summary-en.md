## [eMudhra Intermediate CA Keys Compromised](https://simonwillison.net/2026/Oct/20/emudhra-certificates/) ⭐️ 10.0/10

The private keys for eight eMudhra intermediate certificate authorities were compromised, creating risks for certificates chained to them. In response, eMudhra initiated emergency trust-store remediation, while uv 0.13.4, pip 26.2.2, and Certifi 2026.10.19 were released with updated certificate lists. An attacker holding an intermediate CA private key may be able to issue fraudulent certificates that clients accept, subject to the CA&\#x27;s constraints and client-side validation checks. The compromise therefore affects TLS security and software supply-chain trust broadly because many browsers, operating systems, Linux distributions, and developer tools rely on these certificate chains. Security researchers reported that six compromised intermediates were used for TLS and two for code signing. Users and operators should apply the relevant certificate distrust and trust-store updates promptly; affected certificates should be reissued through an alternative trusted CA where appropriate.

**Background**: A certificate authority uses a private key to sign certificates, and an intermediate CA normally signs end-entity certificates that chain to a trusted root. If an intermediate CA key is stolen, software that trusts that intermediate may accept attacker-signed certificates, while the actual scope depends on certificate constraints and validation policies. Trust stores distributed by major root programs and downstream software therefore need coordinated updates.

## [Proposed Integer Multiplication Algorithm Improves the Quasi-Linear Exponent](https://web.maths.unsw.edu.au/~davidharvey/research/subnlogn.pdf) ⭐️ 9.0/10

A recent paper by David Harvey and Joris van der Hoeven proposes an integer-multiplication algorithm whose running time is o\(n log n\), rather than merely O\(n log n\). The work is accompanied by extensive expert discussion and an independent Lean formalization of related multiplication bounds. An asymptotic improvement over O\(n log n\) would be a major result in computational number theory and algorithm analysis. It could influence future implementations of large-integer arithmetic, cryptographic systems, and other computations that rely on multiplication, although practical gains would still depend on constants and implementation costs. The distinction between O\(n log n\) and o\(n log n\) is essential: the latter approaches n log n from below and represents an asymptotic improvement, not simply the same bound with a different notation. Commenters also emphasized that this result does not directly improve polynomial multiplication over a fixed finite field; the cited state-of-the-art bound there is O\(n log n 4^\{log^\*\(n\)\}\).

hackernews · Hacker News \(热门\) · Oct 22, 02:30 · [Discussion](https://news.ycombinator.com/item?id=50190455)

**Background**: Integer multiplication is a fundamental operation in computational number theory, and its cost depends on the size of the input integers. Schoolbook multiplication takes O\(n^2\) time for numbers represented with n digits, while more advanced methods based on techniques such as Karatsuba multiplication, Fürer-style methods, and fast transforms reduce the asymptotic cost to the quasi-linear range. Harvey and van der Hoeven previously established an O\(n log n\) algorithm, and the newer proposal targets an o\(n log n\) bound. A Lean formalization uses mathlib&\#x27;s TM2 multi-stack-machine model, which is equivalent to multitape machines through a constant-factor reduction.
