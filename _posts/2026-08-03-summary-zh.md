## [Qwen3.8-Max 树立编码与智能体工作流新标杆](https://qwen.ai/blog?id=qwen3.8) ⭐️ 8.0/10

## [开发者工具必须开源以便 LLM 定制修改](https://blog.exe.dev/devtools-must-be-open-source) ⭐️ 7.0/10

一篇博客文章主张开发者工具必须开源，以便大语言模型能够直接修改源代码中硬编码的行为，而无需依赖配置文件、插件系统或用户可调的设置。作者还提出使用自动化定时任务每晚拉取上游更新并将其上的本地 LLM 修改进行 rebase。 该论点挑战了软件设计领域数十年的传统惯例——配置文件、插件 API 和设置面板——主张 LLM 可以完全绕过这些机制，直接以修改代码作为定制层。若该思路被广泛采纳，将重塑开源维护者对代码可读性的优先级排序、终端用户定制工具的方式，以及日常个性化操作所消耗的计算资源与电力。 作者最具代表性的例子是建议使用 LLM 下载、修改并重新编译源代码来改变文本编辑器硬编码的字体大小——批评者认为这相比一行配置变更极其低效且浪费电力。批评者还警告称，由 LLM 这种不可靠的执行者在夜间自动执行 rebase，可能会悄无声息地破坏用户的工作流，因为自动化功能检查无法完全验证主观行为或回归问题。

hackernews · Hacker News \(热门\) · 8月3日 14:15 · [社区讨论](https://news.ycombinator.com/item?id=49156111)

**背景**: Open-source software has long promised users the freedom to inspect and modify the code they run, but in practice most users — including experienced programmers — rely on community contributors rather than editing source themselves. Software customization has historically been abstracted into config files, command-line flags, and plugin or extension systems precisely because reading and patching source is too costly for most users. With the rise of LLM coding assistants such as GitHub Copilot, Cline, and Continue, editing source code on a user&\#x27;s behalf has become far more feasible, which is the premise this blog post builds on.
