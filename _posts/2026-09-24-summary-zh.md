## [ansi2html.py 严重 XSS 漏洞可导致 SourceHut 账户被劫持](https://blog.arusekk.pl/posts/srht-account-takeover/) ⭐️ 8.0/10

安全研究员 Arusekk 披露了 SourceHut 构建日志所使用的 ansi2html.py 库中存在一个可蠕虫化的跨站脚本（XSS）漏洞（CVE-2026-92973），任何能够向 builds.sr.ht 上的构建日志注入文本的攻击者，都可以劫持查看这些日志的用户账户。 该漏洞影响了广泛使用的开源开发平台 SourceHut，而底层缺陷存在于一个共享的 Python 库中，这意味着其他依赖 ansi2html.py 的应用程序也可能面临同样的攻击向量。它凸显了 CI/CD 生态系统中系统性的供应链风险，因为不受信任的构建输出会在 Web 浏览器中渲染。 该漏洞被归类为构建日志中的存储型 XSS：攻击者可以在 ANSI 转义序列中嵌入恶意负载，而 ansi2html.py 在将终端输出转换为 HTML 时未能对其进行清理。由于渲染后的日志与 SourceHut 的认证会话在同一源下提供，注入的脚本可以窃取 Cookie 或令牌，从而实现完整的账户劫持——并且由于负载可以自我复制（即可蠕虫化），它会自动传播给其他查看者。

rss · Lobsters \(技术社区\) · 9月24日 20:38

**背景**: 跨站脚本（XSS）是一类 Web 漏洞，攻击者控制的脚本会在受害者的浏览器中执行，通常可导致会话劫持。ansi2html.py 是一个 Python 工具，用于将带 ANSI 颜色的终端输出（常见于 CLI 工具和 CI 构建日志）转换为 HTML 以在浏览器中显示。SourceHut（sr.ht）是一个开源、注重隐私的开发平台，包括 Git 托管、缺陷跟踪、邮件列表以及通过 builds.sr.ht 提供的持续集成服务。由于构建日志经常包含攻击者可控的输出（例如引用攻击者提供文件名的编译器错误或堆栈跟踪），如果在没有适当清理的情况下将其渲染为 HTML，就会形成典型的注入漏洞。

## [Radicle 披露网络协议中的严重漏洞](https://radicle.dev/2026/09/23/disclosure-of-vulnerability-in-network-protocol.html) ⭐️ 7.0/10
