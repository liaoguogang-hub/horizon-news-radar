## [Anthropic 声称 VP 不等于 VNP](https://github.com/anthropics/formal-math/tree/main/vp-vnp) ⭐️ 9.0/10

Anthropic 发布了一篇形式数学论文，声称 VP 不等于 VNP，从而区分了两类代数计算问题。该论文并未解决 P 与 NP 问题，而是在密切相关的算术复杂性领域提出了一个可能重要的结果。 VP 与 VNP 的分离将阐明多项式规模代数电路和并行计算的能力边界，并可能影响代数算法与复杂性理论的发展。这也凸显了人工智能辅助定理证明在雄心勃勃的数学研究中的日益重要的作用。 VP 和 VNP 是 P 与 NP 在代数领域的对应概念，但研究的是字段上的算术计算，而非仅针对 0 和 1 输入的布尔计算。论文明确表示，尚未分析这一结果与相对化或代数化等复杂性理论障碍之间的关系。

hackernews · Hacker News \(热门\) · 11月23日 22:09 · [社区讨论](https://news.ycombinator.com/item?id=50620102)

**背景**: P 与 NP 问题询问的是，任何能够高效验证其解的问题是否也能被高效求解。VP 与 VNP 针对代数计算提出类似问题：非确定性多项式规模代数电路可解的问题，是否也能由确定性的多项式规模电路求解。此类分离将是复杂性理论的重要进展，但本身并不等于解决 P 与 NP 问题。

## [Stalwart 成为微软 Exchange 的直接替代品](https://stalw.art/blog/microsoft-exchange-replacement/) ⭐️ 8.0/10

Stalwart 1.2.0 现已支持 MAPI over HTTP、Exchange Web Services、Exchange ActiveSync 和 Autodiscover，使组织能够在兼容常见 Exchange 客户端的同时替换微软 Exchange。该版本还提供迁移工具，其中包括用于迁移本地部署 Exchange Server 和 Microsoft 365 数据的 Vandelay 导入导出工具。 Stalwart 对 Exchange 的兼容可能降低迁移成本，并减少组织对微软专有基础设施的依赖，尤其适合希望规避 Exchange 许可费用和运维负担的机构。这也使开源邮件生态能够更实际地支持广泛部署的 Outlook 客户端及其工作流程。 此次公告强调的是协议兼容，而非完整的功能对等：Stalwart 仍缺少公共文件夹、归档邮箱、移动设备管理以及 NTLM/Kerberos 身份验证等能力。社区讨论特别提到 NSPI 和 DCE/RPC 支持的重要性，同时指出监管要求的邮件归档属于需要单独解决的合规问题。
