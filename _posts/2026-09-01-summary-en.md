## [ISM2 identified as first-trimester biomarker for preeclampsia and fetal growth restriction](https://www.nature.com/articles/s41591-026-04573-6) ⭐️ 8.0/10

Researchers led by Miao et al., publishing in Nature Medicine, used serum proteomics from pregnancy cohorts to identify Isthmin-2 \(ISM2\) as a protein involved in extravillous trophoblast invasion, demonstrating that lower ISM2 levels in early pregnancy are associated with increased risk of preeclampsia and fetal growth restriction. Preeclampsia and fetal growth restriction are leading causes of maternal and neonatal morbidity and mortality worldwide, yet reliable first-trimester prediction tools remain limited. A serum-based biomarker like ISM2 could enable early risk stratification, prophylactic interventions \(such as low-dose aspirin\), and improved pregnancy outcomes at scale. The study links a circulating protein level directly to a mechanistic role in trophoblast biology, bridging biomarker discovery with causal insight into placental development. Specific cutoffs, cohort sizes, validation populations, and assay sensitivity/specificity metrics are not detailed in the available summary and would need to be reviewed in the full paper for clinical translation assessment.

rss · Nature Medicine · Sep 1, 00:00

**Background**: Extravillous trophoblasts \(EVTs\) are a specialized placental cell subtype that invade the maternal uterus and remodel spiral arteries during the first trimester, establishing adequate blood flow to the fetus. When this invasion is shallow, the arteries remain narrow, predisposing pregnancies to preeclampsia, fetal growth restriction, and stillbirth. Serum proteomics is a discovery approach that systematically surveys circulating proteins using mass spectrometry to identify candidate biomarkers, which must then be validated in independent cohorts before clinical use.

This demonstrates that large MoE models can be made accessible on consumer Apple Silicon by treating SSD bandwidth as an extension of RAM, potentially democratizing access to frontier-scale local inference and reducing reliance on expensive high-memory workstations or cloud APIs. The project uses expert-offloading \(loading only the active ~6B parameters per token from a 51B-parameter embedding table\) and exposes an Ollama-compatible API; the developer plans to add MTP \(Multi-Token Prediction\) speculative decoding for further speedups, though the 16GB configuration likely runs far slower than the headline 12 tok/s figure.

## [io\_uring Performance Without Kernel Readahead](https://frn.sh/io-uring/) ⭐️ 7.0/10

A detailed technical analysis examines how io\_uring behaves when the Linux kernel&\#x27;s readahead optimization is disabled, revealing performance implications for asynchronous I/O patterns. The article explores the interaction between io\_uring&\#x27;s submission model and traditional page cache prefetching mechanisms. Understanding io\_uring&\#x27;s performance characteristics without readahead is critical for systems programmers optimizing high-throughput storage applications, as it affects how applications should structure I/O submissions. This knowledge helps developers make informed decisions about buffer management and request sizing in production systems. The analysis focuses on scenarios where the kernel&\#x27;s automatic page cache prefetching \(readahead\) is turned off, which can dramatically change performance expectations compared to traditional read/write syscalls. io\_uring, introduced in Linux 5.1, uses shared ring buffers between user space and kernel space for asynchronous I/O submission and completion.

rss · Hacker News \(热门\) · Sep 1, 13:19

**Background**: io\_uring is a Linux kernel interface introduced in version 5.1 that enables asynchronous I/O operations through shared ring buffers between user and kernel space, avoiding the overhead of traditional AIO. Readahead is a long-standing kernel optimization that prefetches file data into the page cache before applications request it, reducing I/O latency. When readahead is disabled, applications must rely entirely on explicit I/O submissions to populate the cache, which can expose inefficiencies or advantages depending on the I/O pattern used.
