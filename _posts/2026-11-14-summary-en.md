## [SpaceX Successfully Catches a Starship Booster in Flight](https://x.com/i/broadcasts/2brajgZlOKRMka) ⭐️ 9.0/10

SpaceX successfully caught the Super Heavy booster from Starship Flight 15 with the launch tower’s “chopstick” mechanism after an earlier attempt was aborted. It was the first successful catch of a Starship booster itself, although the broader landing and reuse sequence still requires further testing. A successful booster catch could reduce recovery time, refurbishment work, and eventually launch costs, helping Starship progress toward fully reusable and rapidly repeatable operations. The achievement also demonstrates SpaceX’s ability to recover increasingly large launch vehicles with ground-based equipment rather than conventional landing legs. The capture used the so-called “Mechazilla” launch tower and its chopstick-style arms, while the booster had previously been the subject of an aborted automated catch attempt. Search results report that Ship 42 reached orbit, but they also indicate that the planned Flight 15 double catch was not completed, so the event should not be confused with a successful catch of the upper stage.

**Background**: Starship is a two-stage, fully reusable launch system comprising the Super Heavy booster and an upper-stage spacecraft. A chopstick catch would let the tower recover the booster directly after its return burn, eliminating landing legs and potentially shortening the interval between flights. SpaceX has already demonstrated chopstick catches of Falcon 9 boosters and Super Heavy boosters, but this event marks the first successful application to a Starship booster.

## [Lovable Apps Exposed Passport Data and 200K Messages](https://www.crissyfield.de/research/lovable-en/) ⭐️ 8.0/10

Researchers found that multiple applications generated with Lovable publicly exposed user records, including passport details and more than 200,000 private messages. The disclosures highlighted insecure database defaults and overly permissive API access in AI-assisted app development. The incidents show that AI-generated applications can make serious data exposure easy for developers with limited security expertise, especially when backend services default to public access. The risk affects platforms, database providers, app builders, and end users whose personal or confidential information may be stored in affected applications. The exposure involved Supabase-backed access with overly permissive database or API permissions, including read-only public keys that could allow access to published records. Community participants cited an October 30 fix, while raising concerns that existing projects might retain permissive defaults; recommended controls include deny-by-default databases, least-privilege access, server-side authentication, and automated authorization tests.

hackernews · Hacker News \(热门\) · Nov 14, 17:43 · [Discussion](https://news.ycombinator.com/item?id=50499017)

**Background**: Lovable is an AI app builder that creates web applications from natural-language prompts, commonly using services such as Supabase for backend functionality. Supabase can protect records with Postgres grants and Row Level Security policies, but those controls must be enabled and configured correctly; the published Supabase guidance recommends grants, RLS, dedicated schemas, and request checks for securing its Data API. AI-generated code does not remove the need for access-control design, and permissive defaults can turn an entire database into publicly readable data when those safeguards are absent.
