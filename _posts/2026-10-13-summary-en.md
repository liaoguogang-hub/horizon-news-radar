## [Parsing JSON at Tens of GB/s in Python](https://lemire.me/blog/2026/10/12/parsing-json-at-tens-of-gigabytes-per-second-in-python/) ⭐️ 8.0/10

Daniel Lemire published a blog post demonstrating how to parse JSON data at speeds of tens of gigabytes per second in Python, using optimized techniques likely built on SIMD-accelerated native libraries such as simdjson. JSON parsing is a common bottleneck in data pipelines, ML preprocessing, and web services. Achieving such extreme throughput in Python, traditionally considered a slow language, significantly narrows the performance gap with C/C++ and could transform how high-volume data engineering tasks are handled in the Python ecosystem. The approach almost certainly relies on bridging Python with native SIMD-optimized C/C++ code via libraries like cysimdjson, rather than pure Python parsing. Such speedups apply primarily to the raw deserialization step; downstream conversion to Python objects \(dataclasses, dicts, Pydantic models\) typically introduces additional overhead measured in microseconds per record.

rss · Lobsters \(技术社区\) · Oct 12, 15:24

**Background**: JSON \(JavaScript Object Notation\) is the de facto standard data interchange format for web APIs, configuration files, and data pipelines. SIMD \(Single Instruction, Multiple Data\) is a CPU feature that allows one operation to be applied to many data points simultaneously, dramatically speeding up parsing of structured text. simdjson, created by Daniel Lemire himself, is a well-known C++ library that exploits SIMD instructions to parse JSON at billions of bytes per second, and Python bindings \(pysimdjson, cysimdjson\) have been developed to expose that performance to Python users. The standard library&\#x27;s json module is much slower because it is implemented in pure Python C code without SIMD optimizations.

## [Final Menstrual Period Marks Abrupt Physiological Shift](https://www.nature.com/articles/s41591-026-04614-0) ⭐️ 8.0/10

A population-scale study published in Nature Medicine reveals that the final menstrual period represents an abrupt, multisystem physiological transition point, rather than a gradual decline. The researchers used a novel computational framework to analyze cross-sectional laboratory data from two independent cohorts, finding that sex hormone changes begin more than 10 years before menopause onset. This finding challenges the prevailing view of menopause as a gradual hormonal transition and identifies a distinct physiological cliff that could serve as a precise biomarker for clinical interventions. It has significant implications for women&\#x27;s health research, potentially reshaping the timing of hormone therapy, cardiovascular risk assessment, and bone health monitoring. The study employed a novel computational framework applied to cross-sectional laboratory data from two independent cohorts, enabling population-scale inference of the timing and nature of physiological changes. The key finding is that while sex hormone shifts begin more than a decade before menopause, the final menstrual period itself acts as a discrete boundary where multiple physiological systems shift abruptly.

rss · Nature Medicine · Oct 12, 00:00

**Background**: Menopause is officially defined as 12 consecutive months without menstruation, typically occurring between ages 45 and 55, with an average age of 51 in the United States. The menopausal transition is generally understood as a gradual process driven by declining ovarian function, during which progressively anovulatory cycles occur until menstruation ceases entirely. Sex hormones such as estradiol fluctuate during this transition, while gonadotropins \(FSH and LH\) rise to maintain normal circulating estrogen levels until late in the transition.

## [Codex CLI ships persistent self-updating daemon by default, sparking complaints](https://github.com/openai/codex/issues/48195) ⭐️ 7.0/10

OpenAI&\#x27;s Codex CLI was found to install a persistent, self-updating background daemon by default with no documented opt-out. The daemon leaves behind pid files, lock files, and old versions consuming roughly 12 GB of disk space, and has been reported to randomly corrupt file permissions during auto-updates. This issue affects the trust and usability of a widely adopted AI coding tool, as silent background processes, uncontrolled disk consumption, and permission corruption can disrupt developer workflows and version-controlled repositories. It also raises broader questions about default behavior expectations for CLI tools versus full desktop applications in the AI coding agent space. The daemon can currently be disabled via an undocumented feature flag \`daemon\_auto\_start = false\` under \`\[features\]\` in \`~/.codex/config.toml\`. Users have also worked around it by replacing its pid and lock files with symlinks to \`/dev/null\` and marking them immutable with \`chattr +i\`. Several users note the operational model mirrors Anthropic&\#x27;s Claude Code, which similarly retains old versions in \`~/.local/share/claude/versions/\`.

hackernews · Hacker News \(热门\) · Oct 12, 18:29 · [Discussion](https://news.ycombinator.com/item?id=50060694)

**Background**: Codex CLI is OpenAI&\#x27;s open-source terminal-based coding agent, installed via npm and designed to drive OpenAI&\#x27;s coding models locally on a developer&\#x27;s machine. A background daemon is a long-running background process separate from the interactive session; it can enable persistent state, faster startup, and background tasks, but it also keeps running after the user closes the tool, can auto-update itself, and may consume resources without the user&\#x27;s knowledge. The expectation for a CLI tool is typically that it runs only when invoked and does not modify itself silently in the background.

## [Show HN: PS2 Games Statically Recompiled to WebAssembly](https://github.com/snuri00/ps2-web-recomp) ⭐️ 7.0/10

Developer snuri00 has open-sourced a tool on GitHub that statically recompiles PlayStation 2 games into WebAssembly, allowing them to run directly in a web browser without a traditional emulator. This represents a significant technical achievement because the PS2&\#x27;s Emotion Engine \(MIPS R5900\) architecture is notoriously complex, and translating it to WASM enables zero-install, cross-platform preservation of classic games in browsers. It is part of an emerging trend of cross-platform recompilation tooling that could reshape how retro games are distributed and played. Unlike emulation, which translates instructions at runtime, static recompilation converts the game&\#x27;s machine code ahead of time into native-equivalent code on the developer&\#x27;s machine, yielding better performance and tighter platform integration. The project is limited in scope to a single game or small set of titles and faces challenges from PS2-specific features like the VU1/VU0 vector units.

hackernews · Hacker News \(热门\) · Oct 12, 06:46 · [Discussion](https://news.ycombinator.com/item?id=50052251)

**Background**: Static recompilation is a technique that translates a game&\#x27;s original machine code into code for a different target architecture ahead of time, producing a native-like port rather than emulating instructions one-by-one at runtime. The PlayStation 2, released in 2000, uses Sony&\#x27;s custom Emotion Engine processor built on the MIPS R5900 architecture along with dedicated vector units, making it one of the most challenging consoles to emulate or recompile. WebAssembly \(WASM\) is a binary instruction format designed for near-native execution speed in web browsers, and recent projects have increasingly targeted it as a delivery format for retro game engines and recompiled titles.
