Cisco disclosed CVE-2026-76460 on September 16, 2026, a CVSS 10.0 authentication bypass in Cisco Identity Services Engine \(ISE\) and ISE-PIC that allows unauthenticated remote attackers to gain root access via a crafted request to an API endpoint. Cisco PSIRT has confirmed active exploitation, and the vulnerability affects all configurations across ISE releases 3.1 through 3.5, with no workaround available. Cisco ISE is a market-leading network access control \(NAC\) platform that governs who and what can connect to enterprise networks, so root-level compromise of an ISE appliance lets attackers silently rewrite access policies, pivot into internal subnets, and undermine zero-trust architectures that depend on ISE. With confirmed in-the-wild exploitation and over 4,000 ISE instances observable on the internet, the operational urgency for enterprise defenders is extremely high. The flaw stems from insufficient authentication enforcement on an API endpoint, and attackers can additionally delete log entries to obstruct forensic investigation—a specific IoC to watch for is activity around a &\#x27;dummyuser&\#x27; account in access logs. Cisco has shipped fixes as 3.1 Patch 12, 3.2 Patch 11, 3.3 Patch 12, 3.4 Patch 7, and 3.5 Patch 4; in the absence of a workaround, defenders should restrict management interfaces with infrastructure ACLs and prioritize patching immediately.

rss · Dev.to · Sep 19, 17:40

**Background**: Cisco Identity Services Engine \(ISE\) is a next-generation network access control \(NAC\) and security policy management platform that unifies and automates role-based access control across wired, wireless, and VPN environments, and is a cornerstone of many zero-trust architectures. CVSS \(Common Vulnerability Scoring System\) is an open standard for rating vulnerability severity; a score of 10.0 represents the maximum possible severity in CVSS v3.1, meaning the flaw is network-exploitable, requires no authentication or user interaction, and yields a severe confidentiality, integrity, and availability impact. An authentication bypass on an API endpoint means the server fails to verify the caller&\#x27;s identity before processing a request, so any attacker who can reach the endpoint can invoke privileged operations directly.

## [Cloudflare Saves 100TB RAM with Math-Based Load Balancing](https://blog.cloudflare.com/saving-100-tb-of-ram-with-math/) ⭐️ 8.0/10

Cloudflare engineers redesigned their Pingora-based load balancing service by replacing large hash-ring lookup tables with a more memory-efficient statistical approach using Rust, reclaiming over 100TB of RAM across their global network—approximately a 90% reduction in that service&\#x27;s memory footprint. At Cloudflare&\#x27;s scale, even small percentage optimizations translate to massive absolute resource savings, reducing infrastructure costs and energy consumption. The approach demonstrates how revisiting fundamental assumptions in well-established algorithms can yield outsized gains in large-scale distributed systems. The optimization targeted the pingora-ketama component, which stored large numbers of virtual hash points per server to enable consistent hashing. By applying probabilistic analysis, engineers determined they could drastically reduce the number of virtual points per server while maintaining adequate load distribution quality.

hackernews · Hacker News \(热门\) · Sep 18, 18:51 · [Discussion](https://news.ycombinator.com/item?id=49758580)

**Background**: Consistent hashing is a widely used technique in distributed systems for distributing requests across pools of servers while minimizing disruption when servers are added or removed. The traditional implementation, known as a &\#x27;hash ring&\#x27; \(with ketama being one popular variant\), assigns multiple virtual points per server to ensure even distribution, but this requires storing a large lookup table in memory. Cloudflare&\#x27;s Pingora is their Rust-based proxy framework that handles significant traffic across their network, making any per-request lookup overhead multiplied by request volume a serious concern.
