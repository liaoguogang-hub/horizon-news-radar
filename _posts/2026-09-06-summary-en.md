## [Trusting-Trust Attack Extended Beyond Compilers to Entire Linux Distribution](https://arxiv.org/abs/2607.24888) ⭐️ 8.0/10

A research paper demonstrates that Ken Thompson&\#x27;s classic trusting-trust compiler backdoor attack can be instantiated in the GNU strip utility from binutils, a post-build binary manipulation tool, thereby compromising an entire Linux distribution rather than just compiler outputs. This challenges the widely-held assumption that the trusting-trust attack is fundamentally a compiler problem, expanding the threat surface to other critical build utilities and raising serious questions about supply chain security for any software distribution. The attack is instantiated in GNU strip, a post-build utility that removes symbol information from object files, rather than in the compiler itself. By targeting strip, the attack can propagate backdoors through binary manipulation during the build process of an entire distribution.

rss · Lobsters \(技术社区\) · Sep 5, 10:58

**Background**: Ken Thompson&\#x27;s &\#x27;Reflections on Trusting Trust,&\#x27; presented in his 1983 Turing Award lecture, described a theoretical attack in which a compromised compiler inserts a backdoor during compilation and reproduces itself even when the compiler is rebuilt from clean source code. The attack exploits the fact that users typically trust the compiler binary but cannot verify that the binary matches the source. The GNU strip utility is a widely-used post-build tool from binutils that discards symbols and debugging information from object files, making it an integral part of nearly every Linux distribution&\#x27;s build process.

It benefits Debian Code Search users with faster indexing and querying, and serves as a practical reference for other Go developers seeking to leverage SIMD for performance-critical workloads. TurboPFor is known as one of the fastest integer compression libraries, leveraging SIMD instructions like AVX2 for parallel processing. The implementation relies on Go&\#x27;s experimental archsimd package, which exposes architecture-specific SIMD intrinsics through a two-level API design that does not require changes to the Go language itself.

SIMD \(Single Instruction, Multiple Data\) allows a CPU to perform the same operation on multiple data points simultaneously using wide vector registers. Go&\#x27;s archsimd package, proposed in golang/go issue \#73787, introduces compiler intrinsics that allow Go programs to generate inline SIMD instructions from portable code.
