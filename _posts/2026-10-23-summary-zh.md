## [研究人员宣布成功攻破 iPhone](https://blog.calif.io/p/iphone) ⭐️ 9.0/10

研究人员演示了如何利用此前开发的漏洞利用程序和技术方法，实现他们设定的攻破 iPhone 目标。所给新闻链接至详细技术文章，但现有内容未说明具体漏洞链、受影响的 iPhone 型号或 iOS 版本。 成功攻破 iPhone 之所以重要，是因为它是对高级移动安全研究的实际演示，而非仅停留在理论层面的漏洞利用。其更广泛的影响还取决于受影响的设备和系统版本，以及该方法能否被复现或用于受控研究环境之外。 公开的 iPhone 越狱工具链通常会组合 BootROM、iBoot、SPTM、TXM 和内核补丁等多个阶段，其中绑定式越狱每次重启后都需要连接电脑。现有研究还区分了绑定式、半绑定式、半非绑定式和非绑定式越狱，并称 iOS 15 及之后版本没有活跃的非绑定式越狱；但现有材料没有说明研究人员具体采用了哪种方法。

## [OpenSSL 4.1.0 发布，带来重大密码学更新](https://github.com/openssl/openssl/releases/tag/openssl-4.1.0) ⭐️ 9.0/10

OpenSSL 发布 4.1.0 功能版本，加入了多项新功能以及可能不兼容的变更。现有资料显示，4.1.0 开发系列增加了原生 DTLS 1.3 支持，并深化了对 NIST 后量子密码算法的集成。 OpenSSL 是广泛用于互联网服务、TLS 实现和软件供应链的基础密码学工具包，其重大版本更新可能影响众多下游应用。对 DTLS 1.3 和后量子密码的支持，也体现了行业推进安全通信现代化并应对量子威胁的努力。 GitHub 发布页面将 OpenSSL 4.1.0 定义为包含重大且可能不兼容变更的功能版本，因此开发者应查阅迁移指南并充分测试兼容性。现有资料提到了 DTLS 1.3 和后量子算法集成，但没有提供完整发布说明、受支持算法列表或详细的 API 变更。

## [个体化 mRNA 疫苗将黑色素瘤死亡和复发风险降低 42%](https://arstechnica.com/health/2026/10/personalized-mrna-cancer-vaccine-cut-melanoma-death-recurrence-by-42/) ⭐️ 9.0/10

Moderna 与 Merck 宣布，其个体化 mRNA 黑色素瘤疫苗在临床试验中将死亡和复发风险降低了 42%。这种疫苗正在作为已完全切除的高危黑色素瘤的辅助治疗方案，与 pembrolizumab 联合评估。 这一结果可能推动个体化癌症疫苗从实验室概念走向黑色素瘤的常规临床应用，并影响术后高复发风险患者的治疗方式。该疗法还可能启发其他癌种的临床研究。 该疗法为 mRNA-4157，也称 V940 或 intismeran autogene，其目标是攻击患者肿瘤特有的新抗原。所报告的效果来自该疫苗与 pembrolizumab 的联合治疗，而非疫苗单药；现有内容未提供样本量、随访时间、统计指标或安全性结果。

rss · Ars Technica · 10月22日 22:12

一项针对 15,534 条去重工程职位信息的分析发现，在同一家公司内，远程岗位公布的薪酬中位数比现场岗位低 11.5%。在包含明确年薪区间的职位中，薪资披露率从 Ashby 的 53.5%和 Greenhouse 的 45.4%到 Lever 的 9.5%差异显著。 这一发现可能影响薪酬谈判、招聘做法以及工程人才对远程岗位薪资的预期。结果还表明，薪资透明度在很大程度上取决于招聘平台，这既增加了薪酬数据收集的难度，也可能让公开薪资的雇主获得可见度优势。 工程岗位的比较使用了 6,826 条列明年薪区间的职位信息，并要求同一职位族中远程和现场两类各自至少有 60 条记录。远程工程岗位的薪酬中位数为 207,094 美元，现场工程岗位为 234,000 美元；所有职位类型的远程与现场总体差距为 9.7%，但这项观察性分析不能证明远程办公导致薪酬较低。

rss · Dev.to · 10月23日 19:33

**背景**: 薪酬中位数通常由职位公布区间的下限与上限相加后除以二计算得出。申请人跟踪系统会通过 API 公开职位信息，但各平台的薪资结构和披露方式不同：Ashby 提供结构化薪资字段，而 Greenhouse 通常把薪资区间放在自由文本描述中，需要额外解析。该分析通过比较同一家公司、同一职位族内的职位，降低了职位构成差异单独解释差距的可能性。

## [AI 编程生产力取决于交付而非仅仅编写](https://www.nber.org/papers/w35275) ⭐️ 6.0/10

NBER 工作论文 35275 研究了三代 AI 编程工具如何影响开发者生产力，并将编写代码的时间与更广泛的软件交付过程区分开来。该研究使用了超过 10 万名 GitHub 开发者的数据。 如果代码审查、集成、测试或部署仍然构成瓶颈，更快的代码生成未必会带来更多实际交付的软件。这一区分有助于组织依据 AI 编程工具对完成工作的整体贡献来评估其价值，而不是只看原始编码速度。 根据搜索结果摘要，该论文将 AI 编程辅助划分为三个世代，并报告了基于超过 10 万名 GitHub 开发者的证据。其核心衡量区别在于代码编写活动与最终交付结果，但现有材料没有说明具体生产力指标、研究时段或效应大小。
