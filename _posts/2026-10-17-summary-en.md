## [PRIMA retinal implant restores sight in macular degeneration patients](https://www.technologyreview.com/2026/10/16/1145840/prima-implant-restores-sight-macular-degeneration-patients/) ⭐️ 8.0/10

The PRIMA retinal implant system, which was approved in Europe in July and is awaiting FDA clearance in the US, has demonstrated the ability to restore vision in patients with geographic atrophy from age-related macular degeneration \(AMD\), a condition previously considered untreatable in terms of vision restoration. More than 5 million people worldwide suffer from geographic atrophy, an advanced form of AMD in which retinal cells die, and until now no treatment could restore their lost vision. The PRIMA system represents a paradigm shift from merely slowing disease progression to actively restoring functional sight for millions of previously untreatable patients. The PRIMA device is a wireless, subretinal photovoltaic implant of just 2×2 mm, designed to replace damaged photoreceptors by converting near-infrared light projected from special glasses into electrical signals that stimulate surviving retinal cells. Originally developed by Palanker, the system works in conjunction with external glasses that project pulsed near-infrared light onto the implant, with each pixel converting light directly into local electric current to stimulate inner retinal neurons.

rss · MIT Technology Review · Oct 16, 09:00

**Background**: Age-related macular degeneration \(AMD\) is a leading cause of vision loss in people over 60, and geographic atrophy \(GA\) is its advanced dry form, characterized by large, well-demarcated regions of atrophied retinal cells resembling a geographical map. While most current clinical trials focus on slowing GA lesion enlargement, none have been able to restore vision already lost. Photovoltaic retinal prostheses represent an emerging class of devices that restore sight by replacing lost photoreceptors with electronic pixels that convert light into electrical stimulation of remaining retinal neurons, and have been studied for conditions like retinitis pigmentosa and AMD.

## [Deriving Transformers from Associative Memory](https://alexwang.ai/posts/associative-memory/) ⭐️ 7.0/10

Alex Wang published a detailed blog post that derives the transformer architecture step by step from associative memory primitives, showing how attention, key-value lookups, and modern transformer components emerge naturally from memory store formulations. The post walks through the math from first principles, treating each layer as a key-value memory store. 这篇文章为理解Transformer提供了一种替代性的思维模型，可能让那些对传统解释感到困惑的学习者更容易理解这一架构。通过将Transformer框定为记忆系统，它将现代深度学习与认知科学及Hopfield网络中的经典思想联系起来。 The post formalizes a memory store as a function holding M key-value pairs, where queries retrieve values via similarity-based lookup, and derives attention as the natural retrieval mechanism. A key limitation discussed by readers is that storing more keys than the embedding dimension creates interference, a constraint tied to the orthogonality of the key space.

The blog post bridges these two ideas by showing that a transformer&\#x27;s attention layer behaves like a differentiable, soft-retrieval memory store.

## [Chrome and Edge Removing XSLT: What Breaks and What Doesn&\#x27;t](https://doctor-seo.net/en/blog/news/chrome-edge-removing-xslt/) ⭐️ 7.0/10

Google Chrome and Microsoft Edge are planning to remove built-in XSLT \(Extensible Stylesheet Language Transformations\) support from their browsers, following the earlier removal of XSLT processing from Firefox. The change means that XML files linked to XSLT stylesheets will no longer be automatically transformed into HTML for rendering in the browser. This removal affects developers and organizations that rely on browser-side XSLT transformations, particularly in enterprise, government, publishing, and legacy web applications where XML-to-HTML rendering directly in the browser remains common. It signals a broader browser-vendor push to reduce legacy web platform surfaces in favor of JavaScript-based or server-side processing pipelines. The deprecation is primarily motivated by security concerns, as XSLT processing has been a source of historical vulnerabilities. Migration options for affected developers include server-side XSLT transformation, build-time precompilation of XML to HTML, or using a WASM-based polyfill to run XSLT processors in the browser. Firefox dropped XSLT support several years ago, leaving Chrome and Edge as the last major browser engines with native XSLT processing.

## [Risks of Letting LLMs Write Both Code and Tests](https://lobste.rs/s/miwcai/do_you_let_llms_write_both_your_tests_your) ⭐️ 6.0/10

A developer reviewing a merge request observed that when LLMs generate both the code and its tests, the resulting tests are often tautological — they merely restate the implementation rather than verifying behavior. The post proposes adding a team rule that limits LLMs to significantly generating only code or only tests, not both. As AI-assisted development becomes mainstream, this pattern threatens to undermine testing&\#x27;s core purpose: catching bugs. Tautological tests create a false sense of safety and can encode defects as expected behavior, while LLM-induced over-engineering inflates code complexity for the sake of testability, raising maintenance costs across teams adopting LLM workflows. Tautological tests are mathematically or logically incapable of failing because the expected value is derived from the same source as the code under test — a mock, helper function, or constant. The author notes the LLM in the reviewed merge request appeared to over-engineer the production code specifically to enable writing more tests, suggesting LLM-driven development can amplify structural problems when code and tests share a single generator.

rss · Lobsters \(技术社区\) · Oct 16, 23:53

**Background**: Software testing relies on an independence principle: the oracle \(what the test checks against\) must not be derived from the artifact being tested. When this principle is violated — for example, when the test&\#x27;s expected value is computed using the same formula as the code — the test becomes a no-op that always passes, including against incorrect implementations. Over-engineering is a separate but related concern: it refers to adding unnecessary abstraction or complexity beyond what the requirements demand, often justified by speculative future needs. Both problems are amplified in LLM-assisted workflows because the model lacks true independent reasoning and tends to mirror patterns from its own output.
