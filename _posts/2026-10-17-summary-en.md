## [Claude Reveals ECDSA Curve Seed Origins](https://www.anthropic.com/research/ecdsa-curve-origins) ⭐️ 9.0/10

Anthropic researchers used Claude to discover that the seed values for NIST&\#x27;s ECDSA standard curves \(P-192, P-224, P-256, P-384, and P-521\) were generated using the C library&\#x27;s lrand48 pseudorandom number generator seeded with Unix timestamps, rather than being derived from any hash algorithm. This discovery debunks decades-long conspiracy theories about potential NSA backdoors hidden in NIST&\#x27;s elliptic curve parameters, as the mundane origin \(a simple PRNG\) suggests the seeds were not deliberately crafted with hidden weaknesses. It also represents a landmark application of AI to historical cryptographic analysis, demonstrating Claude&\#x27;s ability to solve long-standing open puzzles. Claude solved the puzzle in under half an hour. However, the fifth binary seed, B-163, remains unexplained and does not fit any method Claude attempted; one plausible explanation is a simple typo somewhere in the publication chain. The finding confirms the generation method but not the selection process—candidates could still have been filtered by searching over timestamps.

hackernews · Hacker News \(热门\) · Oct 16, 18:55 · [Discussion](https://news.ycombinator.com/item?id=50122800)

**Background**: ECDSA \(Elliptic Curve Digital Signature Algorithm\) is the most widely used elliptic curve cryptography standard, adopted by NIST in 2000 as part of FIPS 186-2. The standard defines several curves \(like P-256\) that are used globally for digital signatures in TLS, cryptocurrencies, and many other security protocols. The seeds used to generate these curves have been the subject of speculation for decades, with some researchers suspecting that the NSA had intentionally selected weak curves to allow decryption. The lrand48 function is a linear congruential pseudorandom number generator from the C standard library that is NOT considered cryptographically secure, but it was sufficient for generating curve parameters whose security derives from the mathematical properties of the curves themselves, not from the randomness of the seed.

## [Reconstructing Transformers from Associative Memory](https://alexwang.ai/posts/associative-memory/) ⭐️ 8.0/10

Alex Wang published a pedagogical blog post that derives the transformer architecture from scratch using associative memory and key-value retrieval as the foundational abstraction. The walkthrough frames self-attention as a non-parametric memory store and progressively builds up the full transformer from this conceptual basis. This framing offers an intuitive mental model for understanding why transformers work, making the architecture accessible to learners who may struggle with conventional derivations. It connects modern attention mechanisms to classical ideas from Hopfield networks and associative memory research, suggesting deeper theoretical underpinnings for the field&\#x27;s most important architecture. The post treats self-attention as content-based retrieval in a continuous vector space, where queries are compared against stored keys to retrieve corresponding values, directly paralleling Hopfield-style associative memory. A notable limitation discussed is that recall quality degrades as the number of stored memories grows, illustrating why transformers benefit from multiple attention heads and layered architectures to manage interference.

**Background**: The transformer architecture, introduced in the 2017 paper &\#x27;Attention Is All You Need,&\#x27; relies on a self-attention mechanism that allows each token in a sequence to attend to all other tokens. Recent research has drawn connections between this attention mechanism and Hopfield networks, a classical model of associative memory from neuroscience. Associative memory refers to systems that store and retrieve patterns based on learned associations, and framing attention as such retrieval helps explain why transformers can store and recall vast amounts of factual knowledge in their parameters.

## [37-Year-Old Kernel Bug Exploited for Root on OpenBSD](https://calif.io/research/big-fish) ⭐️ 8.0/10

Security firm Calif disclosed a proof-of-concept exploit chain dubbed &\#x27;Big Fish&\#x27; that achieves local privilege escalation to root on fully patched OpenBSD 7.9 by chaining a 37-year-old shared memory integer overflow bug \(originating from the original BSD source code\) with a kernel use-after-free and an out-of-bounds write. This exploit chain defeats multiple OpenBSD hardening mechanisms including KARL, SMAP, and SMEP, demonstrating that even the most security-focused BSD variant is not immune to long-dormant legacy flaws — a sobering reminder that legacy code inherited from decades-old codebases remains a persistent attack surface in modern OS kernels. The root cause is a signed 16-bit counter used in the shared memory accounting code, inherited from the original BSD codebase, which overflows and chains into a kernel use-after-free and a separate out-of-bounds write. Notably, despite KARL randomizing kernel function and data addresses on each boot, the kernel&\#x27;s memory allocators remain deterministic, which the exploit leverages.

rss · Lobsters \(技术社区\) · Oct 16, 15:41

**Background**: OpenBSD is widely regarded as one of the most security-focused UNIX-like operating systems, employing numerous mitigations such as KARL \(Kernel Address Randomized Link\), SMAP \(Supervisor Mode Access Prevention\), and SMEP \(Supervisor Mode Execution Prevention\). The OpenBSD kernel is historically derived from the original BSD \(Berkeley Software Distribution\) codebase dating back to the late 1980s. Integer overflow vulnerabilities occur when an arithmetic operation produces a value that exceeds the storage capacity of the intended data type, wrapping around and causing unexpected behavior. Privilege escalation exploits aim to elevate a normal user account to root \(administrator\) by chaining multiple vulnerabilities together.
