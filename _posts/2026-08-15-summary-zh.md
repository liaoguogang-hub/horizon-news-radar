## [重温《免费午餐结束了》：Herb Sutter 2005 年关于并发的警示](http://www.gotw.ca/publications/concurrency-ddj.htm) ⭐️ 8.0/10

这条新闻聚焦于 Herb Sutter 2005 年发表的经典文章《免费午餐结束了》（最初刊登于 Dr. Dobb&\#x27;s Journal）的再次传播及其持续影响力。该文章警告 CPU 主频的扩展已经走到尽头，软件开发必须从根本上转向并发和并行编程，以利用新兴的多核处理器。 这篇文章从根本上改变了软件行业对硬件性能自动增长终结以及编写并发代码必要性的理解。近二十年后的今天，它的预测已被完全验证，仍然是系统程序员理解多核架构的必读文献。 Sutter 文章的技术背景是 2005 年前后 Dennard 缩放定律的失效：此后 CPU 主频停滞在大约 4–6 GHz，单芯片功耗维持在约 100 W TDP。「免费午餐」一词指的是过去几十年中程序员可以依赖新一代 CPU 自动让单线程代码运行得更快，而无需修改代码。

rss · Lobsters \(技术社区\) · 8月15日 10:31

**背景**: 1974 年提出的 Dennard 缩放定律规定了晶体管在缩小尺寸的同时保持功率密度不变，从而支撑了主频和晶体管数量同步增长数十年的技术演进。大约在 2005 年，这一关系失效——主要原因是在小尺寸工艺节点下漏电流加剧以及由此带来的热约束——芯片厂商转而在单个芯片上集成多核，而不是继续提升主频。并发（管理多个随时间推进的任务）和并行（在多个核心上同时执行任务）成为软件工程师必须掌握的核心技能，因为单线程性能的增长实质上已经停止。

macOS 屏幕共享功能中存在一个严重的身份验证绕过漏洞，编号为 CVE-2026-65400，目前正在被活跃利用，远程攻击者可以在无需密码或有效凭证的情况下完全控制 Mac 电脑。 该漏洞尤其危险，因为它影响暴露在互联网上的 Mac，无需任何用户交互或身份验证即可被利用，而且已有攻击者在被入侵的机器上安装门罗币挖矿程序，表明这已经造成了真实的危害而非仅仅是理论风险。 该漏洞源于不当的状态管理，在建立远程会话之前未能验证凭证（CWE-287），研究人员还发现了守护进程中 SRP（安全远程密码）登录检查存在第二个独立弱点，可强制生成可预测的共享密钥。

rss · Ars Technica · 8月14日 18:32

**背景**: macOS 屏幕共享是一项内置功能，允许用户通过网络远程访问和控制自己的 Mac，常用于远程办公和 IT 管理。CWE-287 是指软件未能正确验证用户或系统身份的一类身份验证缺陷。虽然苹果的系统完整性保护（SIP）阻止了一些直接执行代码的路径，但研究人员演示了一种替代路径，即植入一个无需密码的 sudo 规则和一个 shell 启动钩子。

作者详细审视了自己为一个 AWS 代理编写的 IAM 策略——该代理用于读取一个 Secrets Manager 密钥并调用 Bedrock 上的 Claude 模型——发现 Bedrock 语句使用了过于宽泛的通配符（anthropic.claude-\* 和 bedrock:\*::），实际授予了对所有 Claude 模型的访问权限，而非代码实际调用的那一个特定模型。 过度授权的 IAM 策略是最常见且最危险的云安全错误之一。本文展示了即使谨慎的开发者也可能因依赖直觉而非证据而写出过于宽松的策略，这对任何在 AWS 上部署 AI 代理或工作负载的人来说都是一次值得警醒的教训。 该策略包含两条语句：一条是对单个密钥 ARN 的 secretsmanager:GetSecretValue 进行了严格限制，另一条是对 bedrock:InvokeModel 的资源范围过于宽松。关键洞见在于，策略在语句行数上看似精简，授予的权限却远超实际所需——Bedrock 资源 ARN 应当同时锁定具体的模型 ID 和具体的区域。

**背景**: AWS IAM（身份与访问管理）策略定义了身份可以对哪些资源执行哪些操作，最小权限原则要求只授予完成任务所需的最少权限。Amazon Bedrock 是 AWS 提供的用于调用基础模型（如 Anthropic 的 Claude 系列）的托管服务，每次模型调用都需要一个 IAM 角色，并授予限定到特定模型 ARN 的 bedrock:InvokeModel 权限。常见陷阱包括在资源 ARN 中使用通配符（如 \* 或 claude-\*）、附加 AWS 托管的宽泛策略，以及未核对实际授予的权限是否与意图一致。
