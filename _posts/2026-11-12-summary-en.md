## [22-Year-Old PostgreSQL Type Confusion Becomes RCE](https://mehmetince.net/part-3-6-how-i-ended-up-turning-a-22-year-old-postgresql-type-confusion-primitive-into-rce-cve-2026-6460/) ⭐️ 9.0/10

The article describes the weaponization of a 22-year-old PostgreSQL type-confusion primitive into remote code execution, following the author&\#x27;s investigation into a new class of PostgreSQL core vulnerabilities. The PostgreSQL advisory identified as CVE-2026-16239 affects versions before 18.6, 17.11, 16.15, 15.19, and 14.24. A type-confusion flaw in PostgreSQL core can allow an authenticated user to execute arbitrary code as the operating-system account running the database. Because PostgreSQL is widely deployed and database services often run with substantial privileges and access to sensitive data, the issue has significant implications for managed and self-hosted environments. CVE-2026-16239 involves confusion between the types associated with PostgreSQL&\#x27;s &quot;portal&quot; or cursor lifecycle; recreating a cursor or portal with different types can lead to arbitrary code execution. The advisory says versions before PostgreSQL 18.6, 17.11, 16.15, 15.19, and 14.24 are affected, while separately published PostgreSQL advisories also document related type-confusion weaknesses in plperl, plpgsql, SQL-language functions, and internal data-type arguments.

rss · Hacker News \(热门\) · Nov 12, 18:22

**Background**: A type-confusion vulnerability arises when software treats a value as one type while its underlying representation or behavior actually belongs to another. In PostgreSQL, portals are internal execution objects associated with cursors and query operations, so inconsistencies in how their types are tracked and recreated can cross boundaries that the database engine normally enforces.

## [permute\(\) Enables Stateless Pseudorandom Array Iteration](https://andrew-helmer.github.io/permute/) ⭐️ 6.0/10

Andrew Kensler presented permute\(\), a stateless, constant-time function for iterating through an array in a pseudorandom order. It maps an index to another index using a seed, the array length, and the requested index, without requiring a stored permutation. This approach can avoid the memory and setup costs of explicitly storing or generating a shuffled array, which is useful in graphics, rendering, sampling, and other workloads that need randomized processing order. Its stateless design also makes parallel or repeated evaluation easier because each index can be mapped independently. The function generates unique pseudorandom permutations for a given seed by using an invertible hash over a power-of-two index domain, producing a one-to-one mapping across the represented range. The implementation is intended for constant-time, constant-space use, but users must ensure that the domain and seed assumptions match the intended array size.

rss · Lobsters \(技术社区\) · Nov 11, 20:08

**Background**: A pseudorandom permutation rearranges an array&\#x27;s indices so that elements appear in an unpredictable-looking order while remaining a bijection, meaning no element is duplicated or omitted. Stateless iteration differs from ordinary random shuffling: instead of maintaining shuffle state, it computes the remapped position directly from a seed and the current index. This is particularly relevant to ray tracers and physical renderers, where sample decorrelation can improve results without allocating another array.
