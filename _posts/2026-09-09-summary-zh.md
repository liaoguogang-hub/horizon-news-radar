## [NVIDIA 发布 CUDA Rust：两条 GPU 内核开发路径](https://developer.nvidia.com/blog/introducing-cuda-rust-two-tracks-for-writing-gpu-kernels/) ⭐️ 8.0/10

NVIDIA 正式宣布为 Rust 提供 CUDA 支持，提供两种直接用 Rust 编写 GPU 内核的不同方法，而无需包装其他语言编写的代码。两条路径分别是面向 SIMT 模型的 cuda-oxide 和面向较新 Tile 模型的 cutile-rs。 这标志着 Rust 开发者的 GPU 编程可及性大幅扩展，并巩固了 Rust 在高性能计算领域的地位。通过提供原生 GPU 内核编译而非外部函数包装，NVIDIA 正在将 Rust 视为 GPU 开发的一等语言。 cuda-oxide 是一个自定义的 rustc 代码生成后端，通过 LLVM 将 Rust MIR 编译为 PTX，但需要固定版本的 nightly 工具链；而 cutile-rs 已发布在 crates.io 上，支持稳定的 Rust 1.89+，并通过 CUDA Tile IR 对内核 AST 进行 JIT 编译。这两者对应 CUDA 自身支持的两种执行模型：SIMT（CUDA C++ 中使用的传统模型）和较新的 Tile 模型。

rss · Lobsters \(技术社区\) · 9月9日 13:21

**背景**: CUDA 是 NVIDIA 的并行计算平台和编程模型，使开发者能够利用 NVIDIA GPU 进行通用计算。GPU 内核是跨数千个 GPU 线程并行运行的代码单元（类似于函数）。Rust 是一种系统编程语言，以无需垃圾回收的内存安全保证而闻名。传统上，想要 GPU 加速的 Rust 开发者必须在 CUDA C++ 中编写内核，然后通过 FFI 包装器从 Rust 调用它们。SIMT（单指令多线程）模型是经典的 GPU 编程范式，开发者编写线程级代码，而 Tile 模型是用于表达数据并行计算的更新的、更高级的抽象。

## [盗版网站将视频伪装为 WOFF2 字体文件以滥用 Cloudflare 缓存](https://saimanish.com/blog/cloudflare-woff2-cache-abuse/) ⭐️ 6.0/10

安全研究员 Sai Manish 调查了一种盗版分发技术：盗版网站将 MPEG-TS 视频片段以.woff2 扩展名的 URL 提供，使 Cloudflare CDN 将视频内容当作合法字体数据进行缓存。该滥用手段利用了 Cloudflare 边缘基础设施的两条交付路径来可靠地复制和分发盗版视频流。 该技术暴露了 Cloudflare 缓存键和内容类型处理机制中的盲区，使盗版者能够利用受信 CDN 的基础设施实现快速、低成本的全球内容分发。此问题影响 CDN 运营商、安全团队和版权方，并凸显了基于 MIME 类型和扩展名的信任假设如何被大规模滥用所颠覆。 该滥用手段依赖于 Cloudflare 缓存所有以.woff2 扩展名提供的文件，无论其实际 MIME 类型是什么，这意味着 MPEG-TS 传输流视频字节会被存储在边缘缓存中并直接回放。Cloudflare 的缓存欺骗防护（Cache Deception Armor）依赖于源站的 Cache-Control 头，当源站未对非字体载荷设置限制性缓存策略时，该防护可被绕过。

rss · Hacker News \(best\) · 9月9日 18:42

**背景**: WOFF2（Web 开放字体格式 2.0）是 W3C 标准化的压缩字体格式，旨在通过 CSS @font-face 规则高效交付网页字体。浏览器期望.woff2 URL 处返回字体文件，通常不会深度检查其内部二进制结构，只会验证其包含有效的基于 sfnt 的字体数据。Cloudflare 运营着全球 CDN，在边缘服务器上缓存静态和动态内容以降低延迟；其缓存决策基于 URL 模式、文件扩展名和源站提供的 Cache-Control 头，而非深度的内容类型验证。
