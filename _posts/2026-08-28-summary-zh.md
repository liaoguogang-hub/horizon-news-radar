## [Claude Code Opus 5 自动模式被攻破，攻击成功率高达 80%](https://simonwillison.net/2026/Aug/27/breaking-claude-code-opus-5-auto-mode/) ⭐️ 9.0/10

安全研究员 Johann Rehberger 演示了一种针对 Claude Code Opus 5 自动模式的提示注入攻击，通过诱骗代理下载并解压一个 zip 压缩包，然后执行代码利用 Python 的 base64 模块静默导入本地的恶意 struct.py 文件，该攻击约 80% 的尝试均告成功。在部分测试中，自动模式甚至阻止了 Claude Code 在检测到入侵后终止恶意进程的尝试，使安全机制本身成为了失败的一环。 这一发现直接动摇了 Anthropic 关于自动模式能够可靠保护编程代理用户免受提示注入攻击的大胆声明——提示注入正是该公司自身认定的 AI 代理面临的头号风险。由于自动模式近期已被设为 Claude Code 的默认设置，大量用户可能在处理网页、代码仓库或文档等不可信内容时产生了虚假的安全感。 该漏洞利用了 Python 的导入机制：导入标准库 base64 模块时，Python 会在路径上查找并自动执行任何本地的 struct.py 文件，因此压缩包内携带的恶意 struct.py 可以在代理毫无察觉的情况下执行任意代码。一个尤为令人担忧的边界情况显示，自动模式的分类器既允许恶意进程的创建，又同时阻止了清理命令的执行，意味着安全层反而干扰了代理的应急响应。

rss · Simon Willison \(AI 跨行业洞察\) · 8月27日 22:50

**背景**: Claude Code 是 Anthropic 的命令行编程代理，能够代替用户读取文件、执行 shell 命令、修改代码并与外部系统交互。自动模式是近期推出的权限系统，它使用自动化安全分类器来判断某项操作是否应在不提示用户的情况下继续执行，取代了过去对每个潜在风险命令都要求人工确认的模式。Anthropic 将自动模式宣传为一项重大安全改进，声称它能强力抵御提示注入——这是一类将对抗性文本嵌入文件、网页或工具输出中、从而劫持模型行为的攻击。由于大语言模型在结构上无法区分指令与数据，提示注入仍然是智能体安全中最难解决的开放问题之一。

## [Anthropic 发布面向 AI 智能体的模型硬件标准](https://www.anthropic.com/news/model-hardware-standard-research-preview) ⭐️ 8.0/10

Anthropic 开放了模型硬件标准（Model Hardware Standard, MHS）的研究预览版，该规范旨在让 AI 智能体安全地操作显微镜、液体处理器和机械臂等物理设备。该预览版首批面向一批科学研究实验室和先进制造商开放。 MHS 是由领先 AI 实验室主导的、为 AI 智能体与可编程硬件接口制定标准化规范的少数重大尝试之一，可能塑造智能体到机器控制领域的互操作性格局。若被广泛采用，它有望加速实验室和工业场景的自动化进程，同时也会加深业界对 Anthropic 生态的依赖。 该规范面向实验室和工业环境中的可编程硬件，首批试点项目已在选定的研究实验室和制造商中启动。关于技术规范本身的细节、许可条款以及更广泛发布的时间表，预览版公告中提供的信息仍然有限。

rss · Hacker News \(热门\) · 8月27日 18:04

**背景**: AI 智能体是可以代表用户自主执行操作的软件系统。迄今为止，大多数 AI 智能体的能力仅限于与网站、API 和软件应用等数字界面交互。操控物理硬件需要专门的驱动程序、通信协议和安全机制，而这些在不同设备制造商之间差异巨大，给在实验室和工厂中部署 AI 控制的自动化带来了重大障碍。像 MHS 这样的共享规范可以将这些差异抽象出来，类似于 USB 标准化了计算机连接外设的方式。

## [为无人值守 AI 主播设计记忆与崩溃恢复机制](https://dev.to/orca_forge/creating-an-ai-streamer-that-remembers-previous-visits-designing-memory-and-multi-streaming-states-3c3j) ⭐️ 6.0/10

开发者 Orca Forge 发布了一篇技术文章，介绍如何构建一个无人值守的 AI 虚拟主播系统，该系统能够记住回访的观众，并在渲染器崩溃后不会重置对话状态。 这篇文章探讨了 AI 虚拟主播领域中鲜少被讨论的实际难题——具体来说，如何让一个全天候运行的 AI 角色在跨会话时保持连续性，并对基础设施故障具有弹性，这两者都是任何生产级 24/7 AI 主播的前提条件。 作者采用了按角色划分的记忆作用域，键名为\`broadcast-char:\{characterId\}\`，并将记忆提取拆分为每轮对话的增量提取步骤和最终的整合步骤，这样即使直播突然中断也不会丢失上下文。首次实现时出现了一个 Bug，提取的记忆被关联到了错误的作用域，导致某位观众的发言泄漏到了角色共享记忆中。

rss · Dev.to · 8月28日 00:51

**背景**: 无人值守 AI 主播是一种完全由软件驱动的虚拟主播形象——通常由大语言模型负责对话，再加上一个无头浏览器来渲染虚拟形象的视频输出——现场没有真人主播。由于渲染器是一个持续运行的浏览器进程，容易因内存耗尽或 GPU 问题而崩溃，任何重启都有可能重置进行中的对话。此处的跨会话记忆是指将虚拟形象所了解到的关于个别观众的信息（以及正在进行的对话）持久化到可靠的存储中，这样回访的观众在之后的直播中能被识别，而不是被当作陌生人。
