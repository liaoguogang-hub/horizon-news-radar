## [遭入侵的 Optimizely 部署向大型网站投放恶意软件](https://blog.report-uri.com/worlds-largest-brands-infected-with-malware-via-optimizely/) ⭐️ 8.0/10

据报道，遭入侵的 Optimizely 部署向 Zoom 和 GitLab 等服务相关的大型网站访问者注入了恶意 JavaScript。该事件表明，入侵一个广泛部署的第三方网页平台，可能同时危及大量下游客户。 第三方脚本和标签管理平台通常拥有与客户自有代码相同的信任级别和执行权限，因此会形成集中的供应链风险。网站、营销团队和平台供应商可能需要加强供应商隔离、监控、分阶段发布和责任追踪，避免一次入侵演变为大范围感染。 社区讨论称，恶意载荷针对苹果设备，从两个使用 .icu 域名的站点加载 boot.js，并在最高至 iOS 18.6 的系统上创建隐藏 iframe；评论者将相关活动与 Coruna 和 DarkSword 漏洞利用联系起来。该事件还凸显了 Google Tag Manager 等工具缺乏限制所带来的运营风险，包括 JavaScript 体积过大和工程团队监督不足。

hackernews · Hacker News \(热门\) · 11月16日 23:00 · [社区讨论](https://news.ycombinator.com/item?id=50524767)

**背景**: Optimizely 提供实验和功能管理服务，其部署方式通常包括在客户网站中嵌入 JavaScript。Google Tag Manager 等标签管理系统也允许营销团队在无需完整工程发布流程的情况下添加或修改脚本，因而既强大又具有较高依赖风险。供应商部署一旦被入侵，就可能在不直接攻破各网站源服务器的情况下，将恶意代码分发给大量互不相关的网站。

## [Jiff 1.0 发布，带来范围明确的 Rust 日期时间库](https://burntsushi.net/jiff/) ⭐️ 8.0/10

Andrew Gallant 发布了 Jiff 1.0，将其定位为 Rust 生态中面向现代日期时间处理需求的 Chrono 替代方案。该版本提供民用日期与时间、带时区或偏移的日期时间、时间戳、解析和格式化等 API，并重点处理夏令时问题。 Jiff 为 Rust 开发者提供了一个成熟的新选择，并通过“成功陷阱”式 API 突出时区敏感操作，降低误用风险。它强调明确的功能范围，可能促使项目选择更小、更专注的依赖，而不是把日期时间处理视为包罗所有场景的通用需求。 Jiff 仅支持 Unix 时间尺度，其 crate 功能可配置 Rust 标准库集成、Serde 支持，以及是否将 IANA 时区数据库嵌入二进制文件。维护者明确表示 Jiff 并非适合所有场景；社区讨论还提出了对 TAI、UT1 等特殊时间尺度的支持问题。

hackernews · Hacker News \(热门\) · 11月16日 16:53 · [社区讨论](https://news.ycombinator.com/item?id=50519744)

**背景**: 日期时间库在表示民用日期、时间、偏移、时区和经过时间的方式各不相同，而时区规则与夏令时切换经常导致隐蔽错误。Chrono 在 Rust 中应用广泛，但 Jiff 围绕范围明确的 API、显式的时区处理，以及负责任地选择依赖所应实现和不实现的边界进行设计。
